## Как проверялось

Реальный браузер (Chromium 1.62.1, Playwright) против **production-сборки** CMS,
поднятой в контейнере `eqsitecms-frontend` (`make fe-build` + `make fe`).
Ответы backend подменялись на сетевом уровне (`page.route`), поэтому проверялись
фактическая вёрстка, рендер состояний и поведение интерфейса, а не контракт API —
контракт покрыт unit/component-тестами и live smoke backend.

Скриншоты и машинный отчёт: [`vk-user-confirmation-060-ui-qa/`](vk-user-confirmation-060-ui-qa/),
`report.json` содержит по каждому кейсу флаг горизонтального переполнения и список
console-ошибок.

## Найденные и исправленные в ходе QA дефекты

1. **Состояния карточки рендерились без вертикальных отступов.** Каждое состояние
   возвращало фрагмент, а antd `Space` считает фрагмент одним элементом и не
   расставляет отступы между его детьми: инструкция вставала справа от заголовка, а
   абзацы состояния `BLOCKED` слипались («…не доставляются.Откройте диалог…»).
   Исправлено — каждое состояние обёрнуто в собственный `Space direction="vertical"`.
2. **Подписи каналов ломались посимвольно на mobile** («E m ai l»): колонка
   переключателей сжималась. Исправлено — `whitespace-nowrap` на подписи,
   `min-w-0 flex-1` на описании события и `shrink-0` на колонке переключателей.
3. **Ошибка мутации дублировалась** в карточке и в открытом модальном окне.
   Исправлено — в карточке alert показывается только при закрытом модальном окне.
4. **Заголовок состояния `PENDING` дублировал текст тега.** Исправлено — заголовок
   «Привязка аккаунта VK», статус остаётся только в теге.

Все четыре найдены до Quality Gate и закрыты в этом же deliverable; повторный
прогон 27 кейсов после исправлений — без замечаний.

## Ограничение

Прогон выполнен без live CMS-сессии: пароли пользователей `admin` / `su` в
dev-окружении неизвестны, а заводить QA-пользователя в базе не входило в scope
change. Поэтому auth-guard и реальные ответы backend в браузере не проверялись —
их покрывают unit-тесты (`401` для anonymous по каждому маршруту) и live smoke
(`GET /api/vks/me` → `401`, `GET /api/vks/bot-info` → `503`).

**Остаётся владельцу:** один проход под реальной учётной записью `ADMIN`/`SUPERUSER`
после заполнения `VK_GROUP_TOKEN`, `VK_GROUP_ID`, `VK_GROUP_SCREEN_NAME` — вместе с
end-to-end проверкой привязки через реального бота.
