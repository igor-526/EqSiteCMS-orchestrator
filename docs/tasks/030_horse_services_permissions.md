# Контекст
В задачах `027_horse_services_management` и `028_horse_services_management_cont` мы реализовывали механики управления связями услуг и лошадей. Одна из задач была реализация фильтрации лошадей по наличию у неё определённой услуги. Суть в том, что Site Comsumer будет хранить не UUID услуг, а их наименование перед тем, как фильтровать. Это означает, что управлять доступными услугами должен разработчик, а не администратор CMS. Для этого нам нужно корректно настроить права доступа в API Backend и корректно их обработать на CMS Frontend
# Задача
Пользователь с группой dev или su должен иметь возможность полностью регулировать состав услуг и их наименование
Пользователь с группой admin не должен иметь возможности удалить или добавить новые услуги, а также изменять наименование услуги. Что-то подобное было реализовано в `price_groups`. Также на backend необходимо реализовать дополнительный фильтр на эндпоинте получения лошадей. Как фильтр по услугам для CMS по UUID, только по наименованиям услуг
