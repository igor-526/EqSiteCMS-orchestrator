# Инициализация сервиса Яндекс
## Контекст
Мы выполняли задачу  `086_seo_service`. В этой задаче мы инициализировали сервис для SEO аналитики. Сейчас нам нужно создать первого провайдера - это будет сервис интеграции с Яндекс
## Предполагаемая архитектура
Сервис интеграции с Яндекс будет выполнять следующие задачи:
- Хранение зашифрованных авторизационных данных пользователя
	Пользователь будет из UI выполнять авторизацию в сервисах Яндекс. Задачей сервиса будет зашифровать авторизационные данные и хранить их
- Управление аккаунтами Яндекс
	Пользователь также сможет удалять свои привязки аккаунтов Яндекс к приложению
- Предоставление зашифрованных авторизационных данных другим сервисам
	Другие сервисы-парсеры могут требовать авторизационные данные пользователя для выполнения своих задач. Задачей этого сервиса будет предоставить доступ авторизационным данным
- Хранение данных о счётчиках Яндекс.Метрика
	Другие сервисы могут иметь необходимость получать данные для парсинга информации
- Хранение данных о хостах Яндекс.Вебмастер
	Другие сервисы могут иметь необходимость получать данные для парсинга информации
В будущем будет реализован сервис для парсинга данных Яндекс.Метрика и Яндекс.Вебмастер. Для парсинга данных нужно получать авторизационные данные Яндекса. Перед этим пользователь должен выполнить авторизацию. Более того, нужно хранить подключенные счётчики Яндекс.Метрика и хост Яндекс.Вебмастер. Это могут быть разные аккаунты
Пользователь также сможет удалять привязки к Яндекс
## Задача
- Используй шаблон `fastapi-template`. Скопируй его в `services`
- В этом сервисе нам понадобится использование NATS Jetstream. При отвязке аккаунта Яндекс другие сервисы будут обязаны выполнить удаление данных. Проверь согласно howto корректную реализацию интеграций
- Доработай под сервис инфраструктурный docker-compose. БД для приложения - инфраструктура. В docker copose приложения должен быть только сам контейнер приложения и его миграции БД.
- Отделяй env приложения от инфраструктурного. Для подключения к БД стоит продублировать креды. Не стоит поднимать контейнер с env инфраструктуры
- Дополни корневой `Makefile` для работы с этим сервисом
- Для манифеста сервисов используй ссылку `git@github.com:igor-526/EqSiteCMS-yandex-service.git`. В сервисе инициализируй git репозиторий
- После инициализации сервиса запуш "Initial commit" в ветки `main` и `release`
```
git remote add origin git@github.com:igor-526/EqSiteCMS-yandex-service.git
git branch -M main
git push -u origin main
```
- Не делай devops инфраструктуру. На данном этапе папок `.helm` и `.github` быть не должно
- Доработай агентную архитектуру для работы с сервисом. Уже реализована документация SEO сервиса. Агент должен дополнять и дорабатывать эту документацию относительно любых изменений сервиса Яндекс
Результатом выполнения задачи должна быть готовая к разработке инфраструктура. Должны быть подняты БД и сервис в контейнерах
