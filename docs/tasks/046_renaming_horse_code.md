# Контекст
В задаче `025_horse_codes` мы дорабатывали структуру лошадей, добавив туда коды родословной. Проблема в том, что что-то ставится спереди клички, что-то сзади. Плюсом там есть ещё и код страны
# Решение
Мы избавляемся от поля `code` и добавляем поле для клички лошади в родословной. Оно nullable. Назовём его `pedigree_name` Backend при отдаче DTO лошади либо отдает кличку родословной при её наличии, либо  использует основную кличку. Но такой fallback только при авторизации под сервисным кодом конюшни (публичные эндпоинты). При работе в CMS  и авторизации по Cookies поле должно отдаваться в том виде, в котором оно и есть для возможности корректного редактирования
# Данные и миграция
Миграция данных будет одноразовой и под одного клиента. Поле `code` можно терять, важных данных там нет. В миграции смело удаляй это поле и создавай новое
