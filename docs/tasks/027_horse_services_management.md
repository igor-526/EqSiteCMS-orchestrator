# Контекст
Мы реализовывали CRUD по услугам для лошадей
Модуль услуг на frontend находится в разделе "Лошади", вкладка "Услуги"
Нам необходимо до конца реализовать функционал управления связей услуг с лошадьми
# Модель и идея
Модель управления связями лошадей с услугами находится в `services/backend/src/models/horse_service.py` и называется `horse_service_relations`
# Функционал
Идея в том, что пользователь может привязать к лошади одну или несколько услуг. При этом в каждой привязке пользователь может переопределить описание этой услуги (поле `description_override`) и цену (комбинация полей `price_override` и `price_formatter_override`).
# Backend
## Новое API
Необходимо разработать API для управления связей лошадей и услуг с override. Нужны методы добавления связи, удаления и редактирования
## Доработка схемы
Нам необходимо возвращать услуги вместе с лошадьми. Давай добавим в `HorseOutDto` поле `services`, которое будет возвращать список услуг (без page_data). Это поле необходимо возвращать также в любых других схемах, которые включают в себя `HorseOutDto`
# Frontend CMS
Реализовывать UI связи услуг с лошадьми мы будем в табличном представлении списка лошадей. Оно находится в разделе "Лошади", вкладка "Лошади". Таблица имеет колонку "Действия", которая на данный момент рендерит кнопки управления галереей лошадей и родословной. Добавь туда третью кнопку, которая будет отвечать за управление услугами.
## Дизайн кнопки
Подбери наиболее подходящую иконку для этой кнопки (что-то связанное с финансами). По аналогии с фотографиями в правом верхнем углу необходимо отобразить количество связанных с лошадью услуг
## Нажатие на кнопку
При нажатии на кнопку давай открывать [Drawer](https://ant.design/components/drawer) справа на полэкрана, в котором будем отображать таблицу с услугами. Если к лошади не привязана ни одна услуга, то необходимо отображать NoData заглушку и направлять пользователя нажать на кнопку создания. Если услуги есть, то будем отображать таблицу с услугами
## Таблица
Таблица будет представлять собой 2 колонки: "Наименование" и "Цена" по аналогии с реализацией таблицы в разделе "Лошади", вкладка "Услуги"
При нажатии на строку таблицы необходимо открывать модальное окно добавления и редактирования связи с услугой
## Модальное окно добавления и изменения связи
Должно иметь аналогичную логику с добавлением и изменением других сущностей, например
- Раздел "Лошади", вкладка "Лошади"
- Раздел "Лошади", вкладка "Породы"
- Раздел "Лошади", вкладка "Масти"
- Раздел "Лошади", вкладка "Владельцы"
- Раздел "Лошади", вкладка "Услуги"
То есть иметь 2 режима: создание и изменение/удаление
# Frontend Consumer
Изменений не потребуется
# Баги модального окна
На frontend реализован UI добавления и изменения услуги. Там есть некоторые баги валидации.
Аналогичные баги мы исправляли в задаче 026. Ты можешь посмотреть созданные по ней артефакты и diff в одноимённой с задачей ветке
## Обязательный slug
При попытке создать или отредактировать услугу с пустым полем slug (Путь в URL) backend возвращает статус 400 и ошибку "Slug не может быть пустым". Это некорректное поведение. Если не задать slug, то он должен быть сгенерирован автоматически
## Обязательное описание
При попытке создать или отредактировать услугу с пустым полем описания услуги backend возвращает статус 400 и ошибку "Описание услуги не может быть пустым". Это некорректное поведение. Описание услуги может оставаться пустым
# Инструкция
