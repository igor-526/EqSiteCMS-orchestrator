## Карта actions
### 1 - удаление из site-settings
Данное значение не должно управляться администратором. Его нужно удалить из контроллируемых. Перед удалением необходимо проверить фактическое использование значения в CMS Frontend. Если оно используется, необходимо хардкодить это значение прямо в коде. Можно использовать сервисный слой
### 2 - оставляем
Данное значение остаётся и полностью контроллируется администратором конющни
### 3 - блок about
Оставляем в about только 2 блока. Делаем 4 string ключа: `about_1_title`, `about_1_text`,  `about_2_title`, `about_2_text`. Логику с изображениями со страницы пока что убираем, оставляем только 2 заголовка и 2 сплошных текста. Второй title и text могут быть пустыми. Условия для отображения - заполнение и того и другого значения
### 4 - логика с телефонами
На данный момент поддерживаем только 1 главный телефон. Давай оставим ключ `contacts.primary_phone`, который будет управлять телефоном, который указывается в шапке, конатктах и footer. Остальные телефоны пока что не поддерживаем
### 5 - логика работы с услугами
Услуги ищутся по неизменяемому для администратора наименованию группы в API
Описание услуг и вся остальная информация на страницах услуг, где находятся карточки, должна браться по API. Страница может быть кастомизирована дополнительными блоками. Их управление не нужно. Посмотри на реализацию site-ad
### 6 - контакты
Управляться должны координаты карт, адреса, ссылки. Желательно раскидать все на разные ключи. Посмотри на реализацию site-ad
