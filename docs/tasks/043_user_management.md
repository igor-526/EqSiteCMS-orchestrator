# Контекст
Сейчас пользователя можно зарегистрировать только через БД. Я хочу, чтобы у одной конюшни были администраторы, которые могут управлять пользователями
# Новая роль
Для управления другими пользователями у пользователя должен быть отдельный scope. Давай назовём его `USER_MANAGER`. Посмотри систему сидирования и засидируй новую роль
# Доступы
На frontend cms раздел "Пользователи" видит только пользователь с правами `USER_MANAGER` (Дальше в этой задаче буду называть его "UM") или `SU`. 
UM может:
- создать нового пользователя
- изменять данные других пользователей
- удалять пользователя
- видеть всех пользователей, кроме удалённых
- назначать пользователям роли администратора, разработчика и UM
- блокировать и разблокировать пользователей
UM не может:
- самостоятельно восстановить пользователя
- убрать у себя роль UM
- удалить самого себя
- назначить роль SU пользователю
- заблокировать самого себя
- выполнять любые действия с пользователями с правами SU
SU может выполнять все действия со всеми пользователями, кроме удаления, блокировки самого себя и снятия с себя роли SU
# Удаление пользователей
Удаление пользователей должно происходить с помощью soft-delete модели. Если такое не реализовано в БД, то нужно реализовать. Удалённый пользователь не может взаимодействовать с API
# Блокировка пользователей
Нужно добавить в БД флаг блокировки. Заблокированные и удалённые пользователи не должны попадать в выдачу сервисного эндпоинта получения пользователей. Заблокированный пользователь не может выполнять запросы к API
# Backend
Реализовать API управления пользователями
## Эндпоинт получения ролей
Потребуется эндпоинт для получения всех ролей пользователя для заполнения селектора в фильтре. Поддерживает поиск по `scope_name`. Регистронезависимое регулярное выражение
## Фильтры пользователей
- `username` -  принимает str и ищет по регистронезависимому регулярному выражению
- `first_name` -  принимает str и ищет по регистронезависимому регулярному выражению
- `last_name` -  принимает str и ищет по регистронезависимому регулярному выражению
- `middle_name` -  принимает str и ищет по регистронезависимому регулярному выражению
- `scope_ids` - принимает список UUID ролей пользователя. Работает по логике "ИЛИ"
- `search` - принимает str и ищет по регистронезависимому регулярному выражению по first_name, last_name, middle_name одновременно
- `is_blocked` - принимает bool и фильтрует по статусу пользователя
- пагинация как во всём проекте
- `sort` - реализация сортировки как и во всех остальных эндпоинтах по всем полям
## Стандартная сортировка
Стандартная сортировка должна быть сначала по статусу блокировки ASC (сначала не заблокированные пользователи, потом заблокированные). Потом сортировка по last_name ASC
## Эндпоинты действий с пользователями
- удаление пользователя
- PATCH пользователя
- блокировка и разблокировка пользователя
- смена пароля пользователя
# Frontend CMS
В боковом меню необходимо разместить после всех кнопок кнопку, которая переключит пользователя на страницу управления пользователями. Подбери наиболее подходящую для этого иконку
## Header
Там, как и в других разделах размещена пагинация, строка поиска по всем пользователям и кнопка добавления нового пользователя
## Содержимое
Как и в других разделах, список пользователей будем представлять в табличном виде со следующими колонками
### Username
В колонке фильтр и сортировка
### Фамилия
В колонке фильтр и сортировка
### Имя
В колонке фильтр и сортировка
### Отчество
В колонке фильтр и сортировка
### Роль
В колонке фильтр и сортировка
Реализуй в виде разноцветных тегов в спектре от красного до зелёного по значимости роли пользователя. Обязательно fallback на серый цвет, если вдруг роль незнакома
### Забл.
В колонке фильтр и сортировка
Реализуй в виде красного и зелёного тега
### Действия
Рендерит кнопки управления пользователями. Для каждой кнопки подбери подходящую иконку. Кнопки действий необходимо рендерить в соответствие с описанными доступами пользователя
#### Сменить пароль
При нажатии открывается модальное окно. В модальном окне input для ввода нового пароля и второй для подтверждения. Валидация на строгость пароля как в разделе пользователя (там реализован функционал смены пароля самому себе). Внизу кнопка "Сменить пароль"
#### Забокировать/разблокировать
При нажатии кнопки открывается модальное окно с подтверждением намерения пользователя о блокировке или разблокировке в зависимости от текущего состояния пользователя
#### Удалить
При нажатии кнопки открывается модальное окно с подтверждением действия и предупреждением о том, что действие необратимо без участия разработчика
## Модальное окно пользователя
Модальное окно нужно для создания нового пользователя и изменения данных выбранного. Выбор пользователя происходит посредством нажатия на элемент в таблице. Создание нового пользователя активируется при нажатии соответствующей кнопки в верхней части страницы. Подобное поведение в концепции одного модального окна на изменение и создание нового пользвоателя реализовано во всех разделах платформы. Модальное окно позволяет менять фамилию, имя, отчество, username пользователя и его роли
