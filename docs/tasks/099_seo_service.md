## Разработка SEO сервиса

## Контекст

Был развёрнут пустой `seo-service`. Он предназначен для хранения поисковых запросов и страниц сайта. Это общие SEO сущности и потом другие сервисы-парсеры будут обращаться к SEO сервису для того, чтобы получить UUID страниц и поисковых запросов

## Задачи

### Хранение поисковых запросов и страниц

#### Уникальность

Поисковые запросы и страницы могут должны быть уникальны в рамках одного сайта (одной конюшни). В разных конюшнях запросы могут совпадать. Давай не будем делать m2m связь, а будем лучше дублировать, чтобы облегчить задачу поиска в будущем

#### Поисковые запросы

Поисковой запрос - это то, что пользователь вводит в поисковой строке. Он у нас хранится в текстовом виде. Не стоит ограничивать его длину

#### Страница

Страницу мы будем хранить только как путь от основного домена. Длину пути страницы тоже не стоит ограничивать на уровне БД

#### Нормализация поисковых запросов

Поисковые запросы следует нормализовывать следующим образом:

* первая буква заглавная
* остальные все строчные

#### Нормализация страниц

Необходимо реализовать нормализацию страниц по допустимым параметрам и хешам

Настройки нормализации страинц могут быть изменены SEO специалистом

То есть нам необходимо реализовать 2 таблицы для настроек черного списка:

* хеши
* параметры запроса

Пока что в зависимости от этих настроек к существующим страницам ничего не должно быть применено. Это будет одна из следующих задач

### API

#### Получение UUID страниц и поисковых запросов

Нам необходимо реализовать API получения UUID запроса или страницы. Идея такая, что любой сервис-парсер будет присылать пачку запросов или страниц, а задача сервиса будет сначала нормализовать их, а потом в контексте конюшни найти или создать соответствующие запросы или страницы и вернуть сервису-парсеру

Для основного backend эти эндпоинты пока что не нужны, поэтому проксировать их нет необходимости

#### Настройка нормализации страниц

Нужны эндпоинты для управления хешами и параметрами запроса для SEO специалиста

Эти эндпоинты должны быть доступны с основного backend

#### Получение запросов и страниц

В контексте конюшни необходимо получать поисковые запросы и страницы. Из параметров необходима только сортировка по `query`/`page` и регистронезависимый поиск по ним же. Стандартная сортировка по `created_at` DESC

Этот эндпоинт нужен с основного backend

## Не цели

реализация кэширования

удаление и изменение поисковых запросов и страниц

реализация парсинга

создание роли

## Роли

Эндпоинты backend должны быть доступны с роли admin
