# Контекст
Найди задачи и артефакты, в которых мы реализовывали функционал работы формы обратного звонка. Нам нужно хранить эти заявки и выводить их в UI
На данный момент реализована только инфраструктура доставки уведомлений по заявкам на обратный звонок
# Уведомление
На почту на данный момент приходит уведомление, которое содержит UUID заявки и UUID всадника. UUID всадника нигде не передаётся, он не должен нигде фигурировать в коде
В уведомлениях не должно фигурировать никаких UUID. Только информация по самой заявке
# Статусы
Для каждой заявки необходимо держать статусы. Давай их держать в числовом виде, чтобы мы могли сортировать по ним
## Новая
`1`
Статус присваивается автоматически каждой новой заявке на обратный звонок
## Обработана
`2`
Статус проставляется администратором из UI или командой микросервиса. Необходимо будет создать сервисный для изменения статуса заявки на обратный звонок
# UX|UI
## Раздел
Добавь в боковое меню раздел для работы с заявками на обратный звонок последним пунктом. Найди подходящую для этого иконку
## Вкладки
По аналогии с UX/UI других разделов верхним уровнем идут вкладки, фильтры и пагинация

Необходима сортировка

Отображает информацию о статусе заявки в виде тега. При нажатии на тег должно открыться всплывающее меню, в котором пользователь может перемещать заявку между статусами
Необходима сортировка
Необходима множественная фильтрация по статусам

Отображает информацию о том, является ли заявка спамом
При нажатии на значение открывается всплывающий список, в котором пользователь может пометить заявку как спам или убрать этот статус
Требуется сортировка
Требуется множественная фильтрация по статусам спама
#### Имя

В сортировке нет необходимости
Фильтрация по регистронезависимому регулярному выражению

В сортировке нет необходимости

#### Комментарий
Информация с заявки. В таблице обрезаем до адекватных размеров
В сортировке нет необходимости
Фильтрация по регистронезависимому регулярному выражению
#### Нажатие на запись
При нажатии на запись заявки в таблице должно открываться модальное окно, в котором должна структурированно показываться вся информация о заявке

# Доступы
Работа с заявками на обратный звонок доступна для роли администратора и суперпользователя
В UI раздел необходимо выводить только для этих ролей
# Backend
Сделай таблицу для журналирования заявок на обратный звонок
В соответствие с UX\UI реализуй API для работы с заявками на обратный звонок
Стандартная сортировка: `status ASC, created_at DESC`
Стандартный фильтр: `is_spam=False`
На платформе не должно быть возможности создания или изменения заявки, кроме тех полей, которые явно описаны в этом ТЗ
В CMS только смотрим и корректируем статусы заявки и спама. Ничего не удаляем и не изменяем
## Уведомления
Булево поле, говорящее о том, были ли доставлены уведомления или нет по этой заявке. Этот статус проставляет только микросервис уведомлений. Нужен будет служебный эндпоинт для реализации
## Спам
Булево поле, говорящее о том, что заявка является спамом. В будущем классифицировать спам будет ML или другой сервис. Нужен будет служебный метод, который будет выставлять статус спама без изменения статуса заявки. Пользователь может проставлять этот статус самостоятельно. В случае проставления статуса спама заявка должна автоматически перейти в статус "Закрыто". В случае снятия статуса спама пользователем, её статус сохраняется
## Статусы
Так как храним в виде числовых значений, нужно в БД вести реестр соответствия номера статуса с человекочитаемым наименованием и цветом тега
Цвет тега держим в HEX
Информацию сидируем, используя уже готовые механики сидирования в основном backend
Нужен будет метод для frontend для получения информации о статусах. Frontend запрашивает эту информацию при рендеринге страницы с таблицей заявок. Постоянно не хранит
