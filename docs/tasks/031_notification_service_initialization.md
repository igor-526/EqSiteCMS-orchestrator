# Пайплан работы сервиса уведомлений
## Приём действия
Сервис будет принимать события через NATS и понимать, нужно ли уведомление или нет. Если да, то будет его обрабатывать
## Поиск адресатов и каналов
Сервис по метаинформации сделает запрос на основной backend и возьмёт всех пользователей, которым будет релевантно данное уведомление. Это могут быть пользователи определённой конюшни или же вообще все пользователи сервиса. Или только администраторы или разработчики. После сервис сходит в свою БД с настройками пользователей и уведомлений и там уже отберёт пользователей и каналы этих пользователей
## Обработка события
После хэндла события, которое требует уведомления, сервис найдёт это событие в БД в соответствующей таблице. По коду этого события найдёт класс, который будет обрабатывать это уведомления (преобразовывать метаинформацию в текст и прочее форматирование). Для каждого канала в классе-обработчике будет метод, который преобразует уведомление в текст
## Отправка
После обработки сообщения отправляются в канал, на который будут подписаны другие микросервисы, которые отвечают уже за отправку сообщения
# База данных
## Модель для хранения каналов
Модель нужна для хранения доступных каналов доставки уведомлений. Данные в модели должны быть засидированы и не могут быть изменены со стороны API. Read-only

| Поле        | Тип      | Ограничения | Назначение                           |
| ----------- | -------- | ----------- | ------------------------------------ |
| id          | uuid4    |             | Уникальный идентификатор             |
| created_at  | datetime |             | Дата создания канала                 |
| updated_at  | datetime |             | Дата изменения канала                |
| code        | string   | 15          | Кодовое наименование канала (1)      |
| name        | string   | 31          | Человекочитаемое наименование канала |
| description | string   | 511         | Описание канала                      |
| is_active   | bool     |             | Флаг активности канала (2)           |
1 - по кодовому наименованию канала мы будем отсылать в NATS уведомление о необходимости доставки. Каждый метод доставки будет 
2 - по умолчанию True. Может быть переключен в False напрямую в базе данных по инициативе разработчика в случае каких-либо неполадок

## Модель для доступных событий
Модель нужна для хранения доступных событий, которые будут приниматься и обрабатываться сервисом. Данные в модели должны быть засидированы и не могут быть изменены со стороны API. Read-only

| Поле        | Тип      | Ограничения | Назначение                                    |
| ----------- | -------- | ----------- | --------------------------------------------- |
| id          | uuid4    |             | Уникальный идентификатор                      |
| created_at  | datetime |             | Дата создания канала                          |
| updated_at  | datetime |             | Дата изменения канала                         |
| code        | string   | 15          | Кодовое наименование события (1)              |
| name        | string   | 31          | Человекочитаемое наименование события         |
| description | string   | 511         | Описание события                              |
| metadata    | JSON     |             | requided информация для обработки события (2) |
| is_active   | bool     |             | Флаг активности канала (3)                    |
1 - по кодовому наименованию события мы будем искать класс, отвечающий за обработку этого события для дальнейшей доставки уведомления
2 - Будет хранить в себе dict[str, dict[str, str]], на основании которого будет валидироваться событие на корректность информации для дальнейшей доставки уведомления. В качестве ключа будет хранить наименование поля, а в значении будет храниться тип этого поля (в том числе и кастомный. Например, номер телефона) и другие его свойства (например, required)
3 - по умолчанию True. Может быть переключен в False напрямую в базе данных по инициативе разработчика в случае каких-либо неполадок
### Пример данных
```json
[
	{
		"id": "uuid4",
		"created_at": "datetime",
		"updated_at": "datetime",
		"code": "callback",
		"name": "Обратный звонок",
		"description": "Обработка формы заявки на обратный звонок",
		"metadata": {
			"phone": {
				"required": true,
				"type": "phone_number"
			},
			"comment": {
				"required": false,
				"type": "string"
			},
			"equestrian_id": {
				"required": true,
				"type": "uuid4"
			}
		},
		"is_active": true
	}
]
```
## Модель для хранения настроек пользователя
Модель нужна для хранения настроек пользователя. По умолчанию пользователю не будут высылаться никакие уведомления. Пользователь должен явно включить их. Таблица будет хранить, какие уведомления включены у пользователя и по каким каналам

| Поле       | Тип      | Назначение                           |
| ---------- | -------- | ------------------------------------ |
| id         | uuid4    | Уникальный идентификатор             |
| created_at | datetime | Дата создания канала                 |
| updated_at | datetime | Дата изменения канала                |
| user_id    | uuid4    | Идентификатор пользователя в системе |
| action_id  | uuid4    | Идентификатор действия               |
| channel_id | uuid4    | Идентификатор канала                 |
