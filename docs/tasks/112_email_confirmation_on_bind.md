# 112 — Отправка подтверждения при привязке email

Дата: 2026-11-11. Сервис реализации: `services/backend`.

## Исходный запрос

«У нас есть возможность привязки почты для последующей доставки уведомлений. При привязке требуется нажимать на кнопку повторной отправки. Без этого письмо не будет доставлено. Локализуй проблему и давай попробуем её решить на backend стороне, добавив в API флаг отправки письма при привязки email».

## Границы

Локализовать причину по существующему потоку frontend → backend → email-service. Предложить backend-only boolean-флаг, определить default и совместимость текущего frontend, обработку ошибок отправки, повторов и уже подтверждённого адреса, транзакционные границы. Переиспользовать существующий HTTP/Celery-поток без миграций и изменения NATS-контрактов. Реальную доставку SMTP не считать доказанной чтением кода.

Email create/update/delete остаются owner-only без role override; send-confirmation и confirm сохраняют существующие публичные исключения. Фактический метод confirm в проекте — `PATCH`, не `POST`; менять метод в рамках задачи не требуется. Tenant selector не является секретом; там, где он применяется, missing/invalid → `401`.
