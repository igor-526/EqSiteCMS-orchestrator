# Merge страниц при нормализации
## Контекст
В задачах
- docs/tasks/099_seo_service.md
- docs/tasks/100_seo_frontend.md
был реализован сервис `seo-service`, в рамках которого происходит хранение таких сущностей, как поисковой запрос и страница. Там же реализован механизм хранения нормализации путей страниц
В задаче docs/tasks/106_statistics_deleting.md реализован механизм удаления сущностей. Нам нужно воспользоваться подходом удаления для merge страниц
## Задачи
При добавлении правил нормализации страниц по параметрам или по хешу на данный момент со старыми страницами ничего не происходит. Необходимо реализовать механизм, при котором статистика разных страниц будет считаться как одна. В парсере это уже реализовано, мы сейчас обрабатываем кейс добавления нормализаций уже после парсинга
### Добавление нового параметра или хеша нормализации
  При добавлении новых записей SEO сервис должен определить, какие страницы в рамках конюшни должны будут слиты в одну и поставить с помощью NATS соответствующую задачу сервису `ya-metrica-service`. Сервис метрики должен использовать те же механизмы, что и при merge во время парсинга, когда SEO сервис возвращает на разные страницы один и тот же UUID. Делать это нужно отдельной очередью
### Batch
Так как страниц и статистик может быть очень много, делать это необходимо не одним запросом, а несколькими батчами
### Отчёт
Сервис SEO сразу не должен удалять лишние после нормализации страницы. Он только отправляет задание. Сервис метрики же должен после выполнения задания отправить в NATS сообщение SEO сервису о том, что такое задание выполнено и только после этого SEO сервис может удалить лишние страницы
### Защита
При удалении была реализована защита от ситуации, при которой сервис метрики не будет парсить новые данные, пока идёт удаление статистик. Аналогичным образом нужно реализовать следующие защиты:
1. Если на данный момент происходит удаление данных, то задача на merge отменяется, так как в этом не будет необходимости. Отчёт шлётся сразу
2. Если на данный момент происходит парсинг данных, то задача на merge ожидает окончания парсинга
3. Парсинг ожидает выполнения задачи на merge
