# Разработка SEO сервиса
## Контекст
Мы начинаем разрабатывать SEO инфраструктуру, которая будет направлена на более детальный анализ метрик сайта и его содержимого
## Предполагаемая архитектура
SEO сервис будет выполнять следующие функции:
- Интерфейс между основным backend и остальными модулями
	Основной backend будет обращаться только к SEO сервису для взятия данных для ответа или для настройки сервиса
- Хранение основных сущностей
	Есть некоторые сущности, которые должны быть общими при работе других сервисов
	Например, это поисковые запросы или пути страниц сайта
- Оркестрация другими сервисами
	Будут сервисы-парсеры. Например, мы будем парсить метрики сайта. SEO-сервис будет хранить расписание парсингов и ставить задачи в очередь другим сервисам
## Пример архитектуры
Например, я хочу, чтобы у услуг в UI был функционал показа метрик - визиты, отказы и тд
У нас будет сервис `yandex-metrics-parser-service`. Он будет заниматься парсингом всех данных Яндекс Метрики. Задачи на парсинг чего-то отдельного или всего вообще будет ему ставить SEO-сервис. После успешного парсинга SEO-севрис будет хранить поисковые запросы и страницы сайта, а `yandex-metrics-parser-service` будет хранить сами метрики и предоставлять их по запросу SEO-сервиса, который инициализирует основной backend по запросу с frontend
Но для успешного парсинга нужна также авторизация. Для этого нам нужно будет реализовать `yandex-auth-service`, который будет заниматься авторизацией пользователя, хранить авторизационные данные и управлять ими. Парсер будет обращаться к этому сервису для получения необходимых токенов при выполнении задачи на парсинг. Таким образом, мы получим расширяемую микросервисную архитектуру
## Задача
- Используй шаблон `fastapi-template`. Скопируй его в `services`
- Нам понадобится nats jetstram и celery для оркестрации задачами. Проверь согласно howto корректную реализацию интеграций. Доработай под этот сервис инфраструктурный `docker-compose`
- Дополни корневой `Makefile` для работы с этим сервисом
- Для манифеста сервисов используй ссылку `git@github.com:igor-526/EqSiteCMS-seo-service.git`. В сервисе инициализируй git репозиторий
- После инициализации сервиса запуш "Initial commit" в ветки `main` и `release`
```
git remote add origin git@github.com:igor-526/EqSiteCMS-seo-service.git
git branch -M main
git push -u origin main
```
- Не делай devops инфраструктуру. На данном этапе папок `.helm` и `.github` быть не должно
- Сделай в `docs` каталог для хранения документации по SEO-сервису и его модулям
- Доработай агентную архитектуру для работы с SEO-сервисом. Агенты должны направляться на эту документацию, которую мы будем постоянно расширять.
Результатом выполнения задачи должна быть готовая к разработке инфраструктура. Должны быть подняты БД и сервис в контейнерах
