# Ретроспективная спецификация сервисов Яндекса и оформление корневого репозитория

## Исходный запрос (дословно)

«Был реализован в ручном режиме yandex-service и ya-metrica-service. Нам теперь нужно сделать для всего, что там есть спеки и оформить корневой репозиторий».

## Границы первичного задания

PLAN-0: ограниченная инвентаризация существующих сервисов, их Git-метаданных, документации, capability-групп и корневых интеграций; предложение ограниченных последующих planner execution units. На этом этапе полный OpenSpec change не создаётся, approval на реализацию отсутствует.

«Оформить корневой репозиторий» рассматривается как предлагаемая область согласования документации, manifest, compose/env и инструментов с фактическими сервисами; это не разрешение менять runtime, включать сервисы в core release или выполнять deployment.

## Связанные, но отдельные запросы

- [Единая обработка ошибок клиентов Яндекс](096_yandex_client_exceptions.md): отдельный запрос и активный change `normalize-yandex-client-failures`; не заменяет ретроспективную спецификацию всей функциональности.
- [Переход на dependency-injector](095_refactoring_dependency_injector_specs.md): отдельная инициатива; общий DI-refactor не входит в этот запрос автоматически.

Единственным изменяемым реализационным планом последующей работы будет OpenSpec change. Небезопасное наблюдаемое поведение не становится нормативным требованием без явной фиксации gaps и ревью access policy.
