# Планирование задач на парсинг Яндекс.Метрика
## Контекст
В задаче 101 был реализован клиент Яндекс.Метрика и парсинг
В задачах 102 и 103 был реализован UI для вывода информации
Теперь необходимо реализовать автоматическое управление парсингом
## Задачи
### Автоматический запуск
В `.env` давай сделаем настройку в seo сервисе, во сколько нам нужно собирать данные
По сути нам нужно собирать данные ежедневно в это время с учётом часового пояса конюшни (пока что задаётся один на всех в env)
Смотрим все конюшни, у которых привязан счётчик и в это время запускаем парсинг
Парсер должен посмотреть дату последней статистики, она по идее должна быть от вчера и автоматический фильтр дат должен взять 2 дня - сегодня и завтра
Таким образом парсинг обновляет вчерашние данные и добавляет сегодняшние
### Ручной запуск
Помимо автоматического запуска необходимо реализовать эндпоинт ручного запуска. Он уже реализован в сервисе метрики
Но backend должен обращаться только к seo сервису. Этот эндпоинт из сервиса метрики необходимо убрать, так как постановка задачи должна происхоить в NATS
### UI
В UI нам нужно на страницах и на запросах вывести кнопку обновления. При нажатии на эту кнопку должно выводиться модальное окно с подтверждением. После подтверждения SEO сервис должен поставить задачу сервису метрики на парсинг
## Архитектура
Всеми запусками должен управлять SEO сервис
Он должен в NATS отсылать уведомление, которое сервис метрики должен принять и поставить себе задание
То есть вся настройка расписания должна происходить в сервисе SEO и управлять всеми запусками должен он
## NATS
Прочитай в howto по реализации NATS. Создание стримов должно происходить программно
## Расширяемость
У нас потом появятся другие клиенты парсинга, которые будут управляться подобным образом. Продумай расширяемую архитектуру заранее
