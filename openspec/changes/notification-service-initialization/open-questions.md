# Открытые вопросы по notification-service

## Решённые вопросы

### 1. Архитектура и интеграция

**1.1. Стратегия получения пользователей от main backend**
- **Решение:** Вариант A — получать всех пользователей по equestrian_id, затем фильтровать по настройкам

**1.2. Обработка ошибок main backend**
- **Решение:** Вариант C — пропустить уведомление, залогировать ошибку

**1.3. Стратегия кеширования**
- **Решение:** Без кеширования

### 2. Модели данных

**2.1. Уникальность настроек пользователей**
- **Решение:** У пользователя на событие канал либо включен, либо выключен. Unique constraint на (user_id, action_id, channel_id)

**2.2. Каскадное удаление**
- **Решение:** CASCADE удаление. История настроек не нужна

**2.3. Формат metadata для событий**
- **Решение:** Валидацией занимается основной backend. Задача notification-service — обработать событие в том виде, как оно есть, и разослать уведомления

### 3. Безопасность

**3.1. Хранение персональных данных**
- **Решение:** Пока в открытом виде

**3.2. Аутентификация между сервисами**
- **Решение:** Service key достаточно

**3.3. Rate Limiting**
- **Решение:** Пока не нужно

### 4. Производительность

**4.1. Объем трафика**
- **Решение:** Небольшой. Тесты не нужны

**4.2. Задержка доставки**
- **Решение:** Не запариваемся

**4.3. Масштабирование**
- **Решение:** Горизонтально

### 5. Мониторинг

**Решение:** Ничего пока не собираем. Только логируем всё перечисленное

### 6. Тестирование

**Решение:** Согласно QualityGate при планированию (обратить внимание на агента)

### 7. Развертывание

**Решение:** Не запариваемся

### 8. Бизнес-логика

**8.1. Обработка дубликатов событий**
- **Решение:** Вариант B — дедупликация по event_id

**8.2. Retry логика**
- **Решение:** Текущее решение (NATS max_deliver = 5, ack_wait)

**8.3. Обработка ошибок**
- **Решение:** Текущее решение (NATS max_deliver + ack_wait)

### 9. Интеграция с другими сервисами

**Решение:** Отправка события соответствующим микросервисам. Вся остальная логика уже происходит в них. Посмотреть email-service. Сам сервис уведомлений ничего не отправляет пользователям, только команды на отправку

### 10. Future Features

**10.1. UI для управления настройками**
- **Решение:** Нет. Пока только по API

**10.2. Шаблоны уведомлений**
- **Решение:** Хардкод

**10.3. Аналитика**
- **Решение:** Пока нет, сделаем отдельно
