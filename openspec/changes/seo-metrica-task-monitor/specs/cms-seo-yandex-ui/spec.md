# Spec Delta

## MODIFIED Requirements

### Requirement: Страница SEO с вкладками
`/seo` MUST быть Protected Admin UI (anonymous → `/login`) с тремя вкладками «Интеграции» (по умолчанию), «Страницы» и «Запросы». Без SEO MUST отображаться доступное forbidden-состояние без запросов `/api/yandex/**` и `/api/seo/**`. Вкладки MUST сохранять доступность клавиатурой и связи tab/panel на desktop 1366×768; tablet/mobile не входят в поддержку CMS.

#### Scenario: Открытие раздела
- **WHEN** пользователь с ролью SEO открывает `/seo`
- **THEN** видны три вкладки в стиле CMS, активна «Интеграции», существующий сценарий Метрики сохранён

#### Scenario: Прямой заход без роли ADMIN
- **WHEN** пользователь без роли SEO, включая SUPERUSER/DEVELOPER, открывает `/seo` по URL
- **THEN** отображается forbidden-состояние, доступное для фокуса и keyboard-scroll; приватных SEO/Yandex запросов нет

#### Scenario: Анонимный пользователь
- **WHEN** пользователь без сессии открывает `/seo`
- **THEN** выполняется переход на `/login`, защищённый интерфейс недоступен

#### Scenario: Доступные мобильные вкладки
- **WHEN** SEO переключает вкладки мышью и клавиатурой на desktop 1366×768
- **THEN** три вкладки достижимы и читаемы без overlap и горизонтального скролла страницы; tablist/tab/panel связаны, aria-required-children не возникает; mobile/tablet не проверяются

### Requirement: Блок привязки Яндекс.Метрики
Вкладка «Интеграции» MUST содержать карточку «Яндекс.Метрика», загружающую `GET /api/yandex/metrica/connection` и показывающую загрузку, ошибку с повтором, «не привязано» либо «привязано». Заголовок MUST NOT содержать «Подключение» или «Подключения».

#### Scenario: Не привязано
- **WHEN** ответ содержит counter:null
- **THEN** блок сообщает об отсутствии привязки и показывает «Привязать», открывающую визард; кнопки «Задачи» нет

#### Scenario: Привязано
- **WHEN** ответ содержит привязку
- **THEN** блок показывает номер счётчика, данные аккаунта (имя, логин, email, телефон при наличии), «Отвязать» и «Задачи»

#### Scenario: Ошибка загрузки
- **WHEN** запрос завершается ошибкой
- **THEN** блок показывает ошибку и повтор, без мутаций и открытия задач

## REMOVED Requirements

### Requirement: Заглушка Яндекс.Вебмастера
**Reason**: Интеграции объединены, отдельная пустая вкладка больше не нужна.
**Migration**: Удалить вкладку и неиспользуемый WebmasterStub; Метрика находится на «Интеграциях», будущий Вебмастер этим change не реализуется.

## ADDED Requirements

### Requirement: Модальное окно задач
При действующей привязке и актуальной роли SEO кнопка «Задачи» SHALL открывать окно «Задачи Яндекс.Метрики» с пояснением «История задач конюшни, включая предыдущие привязки». Таблица SHALL показывать тип, статус и дату создания; русские подписи типов — «Парсинг метрик», «Слияние метрик страниц», «Удаление данных». Тип/статус MUST NOT передаваться только цветом.

#### Scenario: UI-01 Открытие и доступ
- **WHEN** SEO нажимает «Задачи» мышью либо клавиатурой
- **THEN** открывается окно с фокусом внутри, одна загрузка gateway и таблица; Esc/крестик/«Закрыть» закрывают окно и возвращают фокус на кнопку

#### Scenario: UI-02 Отзыв доступа или привязки
- **WHEN** SEO отозван или состояние привязки стало отсутствующим/другим при открытом окне
- **THEN** окно закрывается, данные и pending UI очищаются; поздний ответ старого запроса не отображается; новые запросы без разрешения не отправляются

### Requirement: Пагинация и состояния задач
Окно SHALL получать список только через backend `GET /api/seo/metrica/tasks`, использовать limit/offset (initial 20/0), серверный порядок без клиентской пересортировки, выбор страниц и размера 20/50/100. Новый размер, повторное открытие или смена привязки SHALL сбрасывать offset=0. Загрузка, пустота и ошибка с явным повтором SHALL быть различимы; автоматического polling SHALL NOT быть.

#### Scenario: UI-03 Страницы
- **WHEN** SEO выбирает вторую страницу, затем размер 50 и переоткрывает окно
- **THEN** запросы содержат соответственно 20/20, 50/0 и 20/0; таблица следует server order; фильтр и пользовательская сортировка не предлагаются

#### Scenario: UI-04 Ошибка и повтор
- **WHEN** GET вернул 400/401/403/502 либо сеть недоступна
- **THEN** отображается безопасная ошибка (401 запускает штатный auth flow), окно не показывает ложную пустоту/успех; повтор только по действию, offset/limit сохраняются

#### Scenario: UI-05 Обновление списка
- **WHEN** SEO нажимает отдельное «Обновить список»
- **THEN** выполняется только GET текущей страницы, не POST; offset за концом непустого total вызывает один переход на последнюю допустимую страницу

#### Scenario: UI-06 Desktop и доступность
- **WHEN** окно открыто на 1366×768 с длинными строками и 100 задачами
- **THEN** заголовок/действия/пагинатор не перекрываются, тело прокручивается внутри окна; Tab/Shift+Tab не выходят за modal, focus видим, фон недоступен
