# Proposal: метрики Яндекс.Метрики на вкладке SEO → «Страницы»

Входной запрос: [`docs/tasks/102_metrics_pages.md`](../../../docs/tasks/102_metrics_pages.md).

Предшествующие изменения:

- 099/100 — seo-service и CMS UI SEO;
- 101 — `metrica-stats-parsing`, архивирован в `openspec/changes/archive/2026-10-26-metrica-stats-parsing/`; specs `metrica-stats-*` синхронизированы в `openspec/specs/`.

## Why

После задачи 101 `ya-metrica-service` накапливает дневную статистику страниц (`metrica_page_stats`), но в CMS она не видна: вкладка «Страницы» показывает только путь и дату создания. Администратору нужно видеть выбранный показатель по страницам за период с агрегацией по дням, неделям, месяцам и годам и сортировать по нему. При этом нельзя допустить N+1 и межсервисную агрегацию в памяти.

## What Changes

### seo-service

- Разрешает период таблицы метрик по новой настройке часового пояса `SEO_UTC_OFFSET_HOURS` (по смыслу как `YA_METRICA_UTC_OFFSET_HOURS`):
  - значения по умолчанию от «сегодня»;
  - выравнивание по границам недели, месяца, года;
  - конец периода не позже сегодняшнего дня;
  - обрезка по лимиту режима со стороны второй даты;
  - календарные колонки.
- `GET /api/pages`:
  - новые параметры `mode`, `metric`, `date_from`, `date_to`;
  - новые сортировки `created_at/-created_at` и `metric:<дата>/-metric:<дата>`;
  - атрибут `metrics_table` в ответе — универсальный DTO таблицы метрик: колонки с заголовками, подсказками и признаком сортировки, разреженные ячейки `{text, value}`.
- Фильтрация, сортировка и пагинация страниц выполняются в SQL seo-service; агрегаты он только преобразует. Добавлен peer-клиент к ya-metrica; при её недоступности seo-service отвечает новым статусом `502`.

### ya-metrica-service

Новые read-эндпоинты класса Private Peer Read. Оба агрегируют одним SQL по готовым границам от seo-service, без календаря, умолчаний и лимитов:

- `GET /api/metrica/page-stats/table` — значения одного показателя по страницам (до 100 UUID) и переданным колонкам (до 31);
- `GET /api/metrica/page-stats/ranking` — упорядоченные UUID страниц по значению показателя в одной колонке (для сортировки).

Агрегация идёт по тем же правилам, что при парсинге и слиянии: аддитивные колонки суммируются, доли, глубина и время — средневзвешенные по визитам.

### backend

`GET /api/seo/pages` принимает и валидирует новые параметры, проксирует их и возвращает `metrics_table` после проверки схемы универсального DTO. Access class (только `ADMIN`) не меняется.

### CMS frontend, только вкладка «Страницы»

- Раскладка: вкладки слева; справа пагинация, «Сбросить» и «Нормализация».
- Ниже — закреплённый блок фильтров «Режим», «Показатель», «Диапазон дат». Все фильтры обязательны, будущие даты выбрать нельзя. Прокручивается только содержимое таблицы.
- Таблица расширяется вправо колонками периода с сортировкой; одновременно сортируется одна колонка.
- «Создано» показывает только дату и сортируется.
- Даты фильтра заменяются итоговым периодом с сервера; при обрезке по лимиту показывается уведомление.
- «Сбросить» снимает только сортировку и поиск по странице.
- `metrics_table` рендерится универсально.
- «Запросы» не меняются.

### Общее

- **BREAKING (внутренний контракт).** Ответ `GET /api/pages` и `GET /api/seo/pages` всегда содержит `metrics_table`, а список страниц зависит от доступности ya-metrica (`502` при сбое). Публичных потребителей у этих маршрутов нет.
- Отсутствие N+1 проверяется автоматическими тестами со счётчиком и логированием SQL, а также live-прогоном с `log_statement=all` на PostgreSQL seo и ya-metrica.

## Capabilities

### New Capabilities

- `seo-metrics-period`: разрешение периода таблиц метрик в seo-service — настройка часового пояса, умолчания, выравнивание по границам режима, ограничение сегодняшним днём, лимит, колонки.
- `metrica-page-stats-query`: агрегация статистики страниц в ya-metrica-service по переданным границам и ранжирование для сортировки; access matrix новых peer-эндпоинтов.
- `metrics-table-contract`: универсальный DTO `metrics_table` — структура колонок и ячеек, правила расширения, форматирование значений и заголовков. Общий для seo-service (производитель), backend (валидация и прокси) и CMS (рендер).

### Modified Capabilities

- `seo-entity-listing`: у списка страниц появляются параметры режима, показателя и периода, сортировки по дате создания и по колонке метрики, атрибут `metrics_table`; агрегаты запрашиваются у ya-metrica.
- `seo-peer-http-contract`: новый статус `502` при сбое ya-metrica и обновлённая строка access matrix для `GET /api/pages`.
- `seo-backend-proxy`: проксирование и валидация новых параметров `GET /api/seo/pages`, возврат `metrics_table`.
- `cms-seo-data-ui`: раскладка вкладки «Страницы», блок фильтров и запрет будущих дат, колонки метрик, сортировка по одной колонке, «Создано» без времени, кнопка «Сбросить» для фильтров колонок, замена дат итоговым периодом и уведомление об обрезке.

## Impact

### Код

| Сервис | Изменения |
|---|---|
| `services/seo-service/**` | разрешение периода, клиент ya-metrica, форматирование, сервис, репозиторий, API; настройки `SEO_UTC_OFFSET_HOURS`, `YA_METRICA_SERVICE_URL`, `YA_METRICA_TIMEOUT_SECONDS` |
| `services/ya-metrica-service/**` | repository, service, API; без миграций и без новых настроек |
| `services/backend/**` | схемы, клиент, API, route inventory |
| `services/frontend/**` | types, api, services, hooks и ui страниц SEO; общий рендер таблицы метрик |

### API

Access matrix — в delta specs `metrica-page-stats-query`, `seo-peer-http-contract`, `seo-backend-proxy` и `cms-seo-data-ui`.

- Новые: ya-metrica `GET /api/metrica/page-stats/table`, `GET /api/metrica/page-stats/ranking`.
- Изменённые: seo-service `GET /api/pages`, backend `GET /api/seo/pages`.

### Git

Работа ведётся в текущей ветке (`main`) каждого сервиса, без создания веток и без коммитов. Остальной git выполняет пользователь.
