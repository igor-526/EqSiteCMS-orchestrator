# Spec Delta: cms-seo-data-ui

## MODIFIED Requirements

### Requirement: Матрица доступа потребляемого API
CMS SHALL использовать только существующие backend операции по матрице ниже, без прямого обращения к seo-service и ya-metrica-service. GET — существующие исключения из Public Read для внутренних SEO-данных, статистики и настроек, запись — Protected Write. Tenant MUST определяться сессией без selector из браузера; SUPERUSER/DEVELOPER без ADMIN MUST NOT заменять ADMIN.

#### Scenario: Контракт восьми операций
- **WHEN** любая потребляемая операция проверяется без сессии, с ADMIN и с другими ролями
- **THEN** ожидаются статусы матрицы; API-boundary тесты покрывают все строки (UT-SEO-01..04 и FT-PM-01..03 для изменённого `GET /api/seo/pages`), UI — UT-SEO-11,15..16, FT-PM-12 и M01..M03,M09..M10, M-PM-01..02

### Requirement: Таблицы сохранённых SEO-данных
CMS SHALL показывать страницы и запросы своей конюшни таблицами на одноимённых вкладках `/seo`. Колонки MUST содержать значение и дату создания; таблица страниц MUST дополнительно содержать справа колонки периода из `metrics_table` ответа. Чтение MUST использовать существующие GET backend с ответом `items/total` (для страниц — также `metrics_table`). Редактирование, создание и удаление страниц и запросов MUST NOT предлагаться.

#### Scenario: Данные и состояния
- **WHEN** ADMIN открывает вкладку «Страницы» или «Запросы»
- **THEN** загружается соответствующий список, показаны значение и дата, UUID служит стабильным ключом; loading, пустой ответ и ошибка с повтором различимы, ошибка не выдаётся за пустой успех

#### Scenario: Длинное значение
- **WHEN** страница или запрос содержит длинное значение
- **THEN** оно не перекрывает дату/колонки метрик/контролы, полное значение доступно через подсказку; путь страницы не превращается в выдуманный URL домена

### Requirement: Серверные фильтр и сортировка в заголовке
Фильтрация SHALL находиться исключительно в заголовке колонки значения. Фильтр MUST передавать `search` с debounce 300 мс и trim; очистка убирает параметр. Сортировка таблицы запросов MUST использовать только `query/-query`. Сортировка таблицы страниц MUST использовать `page/-page`, `created_at/-created_at` или `metric:<дата>/-metric:<дата>` колонки периода; одновременно активна не более одной сортировки, очистка убирает `ordering`. Фильтров по колонке «Создано», колонкам периода и UUID MUST NOT быть; у запросов сортировки по дате MUST NOT быть.

#### Scenario: Поиск и очистка
- **WHEN** ADMIN вводит поисковую подстроку в заголовке, затем очищает фильтр
- **THEN** запрос после debounce содержит search и offset=0; очистка выполняется сразу с offset=0 без search, символы %, _ и обратная косая черта не превращаются клиентом в шаблон

#### Scenario: Сортировка и её сброс
- **WHEN** ADMIN переключает сортировку значения по возрастанию, убыванию и сбрасывает её
- **THEN** API получает соответственно разрешённое поле, поле с минусом и отсутствие ordering; каждый переход сбрасывает offset=0, индикатор соответствует запросу

#### Scenario: Единый паттерн обеих таблиц
- **WHEN** ADMIN открывает «Страницы» либо «Запросы»
- **THEN** иконка поиска находится в стандартной области фильтра справа в шапке колонки значения, как в «Услуги и цены», без отдельной залитой кнопки рядом с названием; открывается выпадающая панель с полем и отдельной кнопкой «Очистить», а не только крестиком внутри поля

#### Scenario: Применённый фильтр и черновик
- **WHEN** ADMIN вводит строку с внешними и внутренними пробелами
- **THEN** draft поля сохраняет введённые пробелы; trim выполняется перед запросом; синяя иконка отражает непустой применённый search, а не ещё не применённый draft; Enter не обходит debounce и не переключает сортировку

#### Scenario: Явная очистка и закрытие панели
- **WHEN** ADMIN нажимает «Очистить» при применённом либо ожидающем debounce фильтре, затем закрывает и снова открывает панель
- **THEN** draft пуст, отложенный поиск отменён, search отсутствует и offset=0; ordering и limit сохранены; панель не закрывается от очистки, после повторного открытия поле остаётся пустым; обычное закрытие панели не очищает draft и не отменяет поиск

### Requirement: Верхняя пагинация таблиц
Пагинация таблицы «Страницы» SHALL находиться справа в строке вкладок, пагинация таблицы «Запросы» — над таблицей, как прежде. Пагинация MUST передавать серверу limit/offset, использовать total из ответа и сбрасывать offset при смене размера страницы. Состояния двух таблиц MUST быть независимы; устаревший ответ MUST NOT заменять актуальную выборку.

#### Scenario: Переходы страниц
- **WHEN** ADMIN открывает таблицу, переходит дальше и меняет размер страницы
- **THEN** начальные limit=25, offset=0; следующая страница имеет offset=25, изменение размера сбрасывает offset=0; page/pageSize в API не передаются

#### Scenario: Изоляция и гонка
- **WHEN** ADMIN переключает вкладки с разными фильтрами либо старый запрос завершается после нового
- **THEN** фильтры/сортировка/offset каждой таблицы сохраняются в пределах посещения `/seo`, отображается только актуальный результат соответствующей таблицы

### Requirement: Модалка нормализации
На «Страницах» SHALL быть кнопка «Нормализация» справа в строке вкладок после пагинации и кнопки «Сбросить». Она MUST открывать модалку с вкладками «Хеш» (по умолчанию) и «Параметры», строкой input с плюсом и компактным списком с иконкой удаления справа. Списки MUST пагинироваться локально после загрузки полного ответа GET, без выдуманных API-параметров.

#### Scenario: Открытие и переключение
- **WHEN** ADMIN открывает нормализацию, меняет вкладку или страницу списка
- **THEN** показана нужная коллекция, локальная пагинация использует размер 10 и число загруженных элементов; при переключении коллекции страница сбрасывается, данные не смешиваются; loading/empty/error с повтором различимы

#### Scenario: Повторное открытие
- **WHEN** ADMIN закрывает и снова открывает модалку
- **THEN** активен «Хеш», первая страница, пустой input, нет старого подтверждения; список загружается заново, поздний ответ закрытого окна не меняет новое

## ADDED Requirements

### Requirement: Раскладка вкладки «Страницы»
На вкладке «Страницы» вкладки SEO SHALL располагаться слева, справа в той же строке — только пагинация таблицы страниц, кнопка «Сбросить» в стиле остальных страниц CMS и «Нормализация» (при разрешении); ниже — отдельная строка фильтров метрик. Строка вкладок и фильтры MUST оставаться видимыми: прокручивается только содержимое таблицы, колонки «Страница» и «Создано» закреплены слева. На 1366×768 элементы MUST NOT перекрываться.

#### Scenario: Прокрутка длинной таблицы
- **WHEN** ADMIN на 1366×768 открывает «Страницы» с 100 строками и 31 колонкой дней и прокручивает таблицу вниз и вправо
- **THEN** вкладки, пагинация, кнопки и фильтры остаются на месте, страница целиком не прокручивается, колонки «Страница» и «Создано» видны

#### Scenario: Другие вкладки
- **WHEN** ADMIN переключается на «Запросы», «Яндекс.Метрика» или «Яндекс.Вебмастер»
- **THEN** пагинация страниц, «Сбросить» и «Нормализация» в строке вкладок не показываются, поведение этих вкладок не меняется

### Requirement: Фильтры метрик страниц
Блок фильтров SHALL содержать обязательные «Режим» (по дням / по неделям / по месяцам / по годам, по умолчанию «по дням»), «Показатель» (8 показателей из `metrics-table-contract`, по умолчанию «Визиты») и «Диапазон дат» (две даты с гранулярностью выбора по режиму). Пустое значение MUST NOT допускаться. При первом открытии и смене режима CMS SHALL запрашивать список без дат и подставлять период из `metrics_table.period`; вычислять значения по умолчанию CMS MUST NOT.

#### Scenario: Первое открытие
- **WHEN** ADMIN впервые открывает «Страницы»
- **THEN** отправлен запрос `mode=day&metric=visits` без `date_from/date_to`, в фильтре диапазона — `period.date_from…period.date_to` из ответа (7 дней)

#### Scenario: Смена режима
- **WHEN** ADMIN, отсортировав по колонке дня, выбирает «по месяцам»
- **THEN** запрос с `mode=month` без дат и без `metric:` сортировки, `offset=0`; диапазон в фильтре заменяется периодом ответа (6 месяцев)

#### Scenario: Смена показателя
- **WHEN** ADMIN выбирает «Доля отказов» при сортировке `-metric:2026-10-20`
- **THEN** запрос содержит `metric=bounce_rate` и ту же сортировку, ячейки показывают значения с `%`

### Requirement: Запрет будущих дат в пикере
Пикер диапазона SHALL блокировать выбор дат и единиц режима, которые целиком лежат после сегодняшнего дня. «Сегодня» берётся из `metrics_table.period.today` последнего ответа, а до первого ответа — по часам браузера.

#### Scenario: Будущие даты недоступны
- **WHEN** ADMIN открывает пикер в режиме «по дням»
- **THEN** дни после сегодняшнего недоступны для выбора

### Requirement: Перевод выбора пикера в даты
Выбранные в пикере значения SHALL переводиться в даты по границам единицы режима:

- неделя — с понедельника по воскресенье;
- месяц — с 1-го по последнее число;
- год — с 1 января по 31 декабря.

Конец, попадающий в будущее, MUST заменяться сегодняшней датой. Окончательные границы определяет сервер.

#### Scenario: Текущая неделя
- **WHEN** сегодня — среда `2026-10-28`, ADMIN в режиме «по неделям» выбирает недели с `05.10` по текущую
- **THEN** отправляются `date_from=2026-10-05&date_to=2026-10-28`

### Requirement: Влияние фильтров на выборку и сортировку
Любое изменение фильтров метрик SHALL сбрасывать `offset=0`. Смена режима или диапазона MUST снимать сортировку по колонке периода; смена показателя её сохраняет. Если сервер вернул `metrics_table.ordering=null` для запрошенной колонки периода, CMS MUST снять индикатор сортировки.

#### Scenario: Смена диапазона при сортировке по колонке
- **WHEN** при `ordering=-metric:2026-10-20` и `offset=50` ADMIN меняет диапазон дат
- **THEN** запрос без `ordering`, с новыми датами и `offset=0`

#### Scenario: Сервер не применил сортировку
- **WHEN** ответ содержит `metrics_table.ordering=null` при запрошенной `metric:` сортировке
- **THEN** индикатор сортировки снят, повторный запрос не отправляется

### Requirement: Обрезка диапазона и уведомление
CMS SHALL отправлять выбранный диапазон как `date_from/date_to` и всегда заменять даты фильтра итоговым периодом `metrics_table.period`. Если сервер только выровнял диапазон или ограничил его сегодняшним днём (`adjusted=true`), замена выполняется без уведомления. Если диапазон обрезан по лимиту (`clamped=true`), CMS MUST дополнительно показать предупреждение с лимитом режима и итоговым диапазоном. Повторный запрос из-за замены дат MUST NOT отправляться.

#### Scenario: Слишком длинный диапазон по дням
- **WHEN** ADMIN выбирает `01.09.2026 – 26.10.2026` в режиме «по дням»
- **THEN** фильтр показывает `01.09.2026 – 01.10.2026`, появляется предупреждение о лимите 31 день, отправлен ровно один запрос

#### Scenario: Выравнивание без уведомления
- **WHEN** ответ содержит `adjusted=true`, `clamped=false` и период, отличный от отправленного
- **THEN** фильтр показывает период из ответа, предупреждения нет, повторного запроса нет

### Requirement: Колонки метрик и единственная сортировка
Таблица страниц SHALL рендерить `metrics_table.columns` справа от «Страница» и «Создано» в порядке ответа универсальным рендером: заголовок — `title`, подсказка — `hint`, ячейка — `text` из `values[row.id]`, иначе `empty_text`, выравнивание — `align`; форматировать значения CMS MUST NOT. Колонка с `sortable=true` SHALL сортироваться прямо и обратно, сортировка одной колонки снимает её с других. Индикатор MUST соответствовать `metrics_table.ordering`.

#### Scenario: Сортировка по колонке периода
- **WHEN** ADMIN нажимает на заголовок колонки `20 окт` дважды
- **THEN** запросы содержат `ordering=metric:2026-10-20`, затем `-metric:2026-10-20`, `offset=0`; индикатор только на этой колонке

#### Scenario: Переключение на другую колонку
- **WHEN** при сортировке по `20 окт` ADMIN сортирует по «Создано»
- **THEN** запрос содержит только `ordering=created_at`, индикатор с `20 окт` снят

#### Scenario: Пустые ячейки
- **WHEN** у страницы нет данных в колонке
- **THEN** в ячейке `—`, остальные ячейки строки не смещаются

### Requirement: Колонка «Создано»
Колонка «Создано» таблицы страниц SHALL показывать только дату `DD.MM.YYYY` без времени и поддерживать сортировку `created_at/-created_at`. Фильтра у колонки MUST NOT быть.

#### Scenario: Дата без времени
- **WHEN** страница создана `2026-10-23T14:05:00Z`
- **THEN** в колонке `23.10.2026`

### Requirement: Сброс фильтров страниц
Кнопка «Сбросить» SHALL сбрасывать только фильтры колонок таблицы страниц: сортировку, применённый поиск по «Странице» и его черновик, с `offset=0`. Режим, показатель, диапазон дат и размер страницы MUST NOT меняться. Сброс MUST отправлять один запрос.

#### Scenario: Сброс после настройки
- **WHEN** ADMIN выбрал «по неделям», «Просмотры», свой диапазон, поиск, сортировку `-metric:2026-10-19` и страницу 3, затем нажал «Сбросить»
- **THEN** отправлен один запрос с теми же `mode=week`, `metric=pageviews`, `date_from`, `date_to` и `limit`, без `search` и `ordering`, с `offset=0`; поле поиска пусто, индикатор сортировки снят
