## ADDED Requirements

### Requirement: Архив новостей с серверной пагинацией
`/novosti` SHALL получать `/api/news?page=N&limit=12` на сервере, выводить intro из `news.intro`, выделенную первую карточку без дублирования в сетке, дату в `site.timezone`, сетку 3/2/1 колонок и обычные ссылки пагинации. Каждая карточка MUST ссылаться на `/novosti/{slug}` из API; client-only inline detail заменяется отдельным маршрутом. Канонический URL первой страницы SHALL быть `/novosti`, последующих — `/novosti?page=N`.

#### Scenario: Пагинация без JavaScript
- **WHEN** посетитель открывает `/novosti?page=2` при total больше 12
- **THEN** HTML содержит вторую страницу данных и ссылки навигации; запрос использует page=2, limit=12, первая карточка не повторяется

#### Scenario: Пустой список и неверная страница
- **WHEN** первая страница имеет total=0 либо query page не является положительным целым
- **THEN** пустая первая страница показывает `news.empty_text`/«Новостей пока нет» с 200; невалидный page перенаправляется на `/novosti`; page за последней страницей с N>1 возвращает 404

#### Scenario: Ошибка данных
- **WHEN** API timeout/5xx или ошибка selector мешает получить архив
- **THEN** выводится отдельное SSR error state с ссылкой повторить запрос и noindex, ошибка не представляется пустым архивом или успешной cached выдачей чужого tenant

### Requirement: Отдельная серверная деталь новости
`/novosti/[slug]` MUST получать `/api/news/by-slug/{slug}` с tenant selector без CMS credentials и рендерить название, дату, фотографии, полный безопасный content, ссылку на архив. `generateMetadata` MUST формировать title из новости, description из snippet/безопасного текста и canonical с точным slug; metadata/page используют согласованные данные одного запроса. `404` upstream MUST приводить к настоящему route 404; 401/5xx/timeout — к error state с noindex, без ложного 404. Неизвестные маршруты остаются 404.

#### Scenario: Прямой вход в опубликованную новость
- **WHEN** crawler без JavaScript открывает ссылку опубликованной новости
- **THEN** исходный HTML содержит полный санитизированный content, заголовок, дату и canonical, без необходимости посетить архив

#### Scenario: Удаление или отложенная публикация
- **WHEN** slug относится к удалённой/будущей/чужой новости либо не существует
- **THEN** route возвращает 404, скрытые данные и metadata новости не раскрываются

#### Scenario: Сбой backend
- **WHEN** lookup возвращает 401/5xx либо timeout
- **THEN** страница показывает техническое состояние с повторным переходом и noindex; content другой новости не используется

### Requirement: Три демонстрационные новости INLOVE
В рамках промежуточной заметки 070 реальная БД tenant INLOVE MUST содержать три идентифицируемые опубликованные mock новости с полным редакционным текстом и стабильными slug. Повторное применение seed SHALL обновлять только свои записи без создания дублей и без удаления существующих новостей. Записи MUST читаться через существующие Public Read API и SSR archive/detail, без mock-only browser transport.

#### Scenario: Повторяемое заполнение и SSR
- **WHEN** seed применяется дважды и anonymous visitor открывает архив и три detail URL
- **THEN** три seed новости существуют по одному экземпляру каждая, их slug стабильны, полный безопасный текст доступен в серверном HTML и чужие tenant данные не меняются
