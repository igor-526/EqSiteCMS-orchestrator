# Уточнение запуска OAuth

## MODIFIED Requirements

### Requirement: Запуск авторизации в мини-окне

Пункт «Добавить аккаунт» MUST получать ссылку `GET /api/yandex/auth/link` и открывать её в popup около 600×700 с сохранением `window.opener`, без информационного баннера ожидания в визарде. Повторный запуск при открытом popup MUST фокусировать его, а не создавать новое окно или запрос ссылки. Ошибки запуска MUST оставаться видимыми.

#### Scenario: Открытие popup
- **WHEN** пользователь нажимает «Добавить аккаунт»
- **THEN** CMS запрашивает ссылку и открывает её в мини-окне, не показывает уведомление «Ожидание авторизации в окне Яндекса. Повторное нажатие вернёт фокус в окно.» и не дублирует его другим pending-баннером

#### Scenario: Popup заблокирован
- **WHEN** браузер заблокировал открытие окна
- **THEN** визард показывает сообщение о блокировке всплывающих окон и предлагает повторить

#### Scenario: Ошибка получения ссылки
- **WHEN** запрос ссылки завершился ошибкой
- **THEN** окно не открывается, визард показывает ошибку

#### Scenario: Повторное нажатие
- **WHEN** пользователь повторно нажимает «Добавить аккаунт» при открытом popup
- **THEN** фокус возвращается в существующий popup, новое окно и второй GET ссылки не создаются, действие не заблокировано самим ожиданием OAuth

#### Scenario: Параллельный запуск
- **WHEN** пользователь активирует добавление несколько раз до завершения получения ссылки
- **THEN** выполняется не более одного GET ссылки и открывается не более одного popup

### Requirement: Обновление списка аккаунтов после авторизации

Визард MUST принимать сообщения только от текущего popup при совпадении origin с `window.location.origin` и типа `eqsite:yandex-oauth`. При `success` MUST перезагружать аккаунты с `offset=0`. Закрытие popup без сообщения MUST завершать внутреннее ожидание и обновлять список. Удаление баннера MUST NOT ослаблять lifecycle/security guards.

#### Scenario: Успешная авторизация
- **WHEN** визард получает сообщение `success` от текущего popup со своим origin и ожидаемым типом
- **THEN** список аккаунтов перезагружается с `offset=0` и содержит новый аккаунт, внутреннее ожидание снимается без pending-баннера

#### Scenario: Чужой origin
- **WHEN** приходит сообщение с другим origin или иным типом
- **THEN** визард его игнорирует

#### Scenario: Окно закрыто вручную
- **WHEN** пользователь закрыл popup до завершения
- **THEN** визард снимает внутреннее ожидание и перезагружает список с `offset=0` без ошибки

#### Scenario: Чужой source или неизвестный статус
- **WHEN** сообщение приходит не от текущего popup либо содержит неизвестный статус
- **THEN** визард игнорирует сообщение, не обновляет список и не считает авторизацию завершённой

#### Scenario: Отмена или ошибка авторизации
- **WHEN** текущий popup присылает допустимое сообщение `error` или `cancelled`
- **THEN** ожидание завершается с безопасным сообщением об ошибке/отмене, успешное добавление не объявляется и список не обновляется как после успеха
