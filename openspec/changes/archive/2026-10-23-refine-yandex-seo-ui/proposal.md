# Уточнение интерфейса SEO Яндекса

## Why

После реализации задачи 098 пользователь уточнил интерфейс: вкладки SEO отличаются от остальных страниц CMS, а выбор аккаунта и счётчика требует лишних действий. Нужен компактный доступный визард с непосредственным переходом/привязкой по нажатию строки без ослабления существующих защит.

## What Changes

- Вернуть канонический паттерн AntD `Tabs` как на страницах настроек сайта и уведомлений, без локальной панели кнопок; сохранить keyboard/a11y и мобильную доступность без прежнего `aria-required-children` блокера.
- Представить аккаунты компактными строками: основная область выбирает аккаунт и сразу открывает шаг цели; отдельная иконка справа открывает только подтверждение отвязки с каскадным предупреждением.
- Удалить «Далее», сохранить «Назад» и расширяемость второго шага. При отсутствии аккаунтов оставить только одну верхнюю подсказку и действие добавления.
- Удалить информационный баннер ожидания OAuth, сохранив повторный фокус popup, обновление при закрытии и проверки origin/type/source.
- Выбор компактной строки счётчика сразу вызывает привязку; удалить отдельные «Выбрать счётчик», «Привязать» и «Обновить счётчики» на втором шаге. Ошибка остаётся на шаге, повтор — осознанным новым нажатием строки, без автоматической повторной mutation.
- Сохранить ADMIN-only, повторную проверку permissions непосредственно перед mutation, синхронную защиту double-submit, ошибки и обновление карточки после успеха.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `cms-seo-yandex-ui`: канонические вкладки, компактные доступные строки, переход при выборе аккаунта, одна пустая подсказка, немедленная привязка счётчика и pending UX.
- `yandex-oauth-cms-callback`: запуск popup без баннера ожидания, при сохранении lifecycle/security guards и однократного обмена кода.

## Impact

Только UI/hooks и близкие тесты `services/frontend/src/features/seo/`. Эталоны: [SiteSettingsTabs.tsx](<../../../services/frontend/src/features/siteSettings/ui/SiteSettingsTabs.tsx#L27-L30>) и [NotificationsPage.tsx](<../../../services/frontend/src/features/notifications/ui/NotificationsPage.tsx#L55-L72>). Переиспользуется `Tabs` из `antd`; отдельного общего компонента вкладок в `src/ui` нет. Для строк выбран семантический `ul/li` с AntD `Button` основной области и отдельной sibling icon-button, не deprecated `List` и не clickable div.

API endpoints, DTO, access policy и серверные контракты **unchanged**: sensitive GET остаются protected, writes — protected, только ADMIN, без role override. Новых/изменённых endpoints нет, новая access matrix не требуется. Backend, peer, consumers, env/config, зависимости, git/tooling вне scope. Кнопка «Привязать» внешней карточки остаётся точкой входа; удаление этой кнопки относится только к шагу счётчиков.

Исходник: [задача 098](<../../../docs/tasks/098_yandex_frontend.md>) и новое пользовательское уточнение PLAN-UI-1. Архив прежнего change и main specs не редактируются. По handoff прежний QG пройден, но финализация заблокирована `shipctl plan: dirty_worktree`; этот change не исправляет и не обходит блокер. Профиль будущей проверки — `QG-FULL` из-за UI behavior diff. Реализация начинается только после пользовательского approval через Router.
