## MODIFIED Requirements

### Requirement: Подтверждение привязки по контрольной строке

`vk-service` MUST нормализовать контрольную строку и подтверждать привязку только после проверки кода, срока действия и отсутствия конфликта VK-отправителя, сохраняя состояние привязки, данные отправителя и факт использования кода.

#### Scenario: Успешное подтверждение

- **WHEN** передан валидный код с `used_at IS NULL` и `expires_at > now()`, а `vk_peer_id` свободен
- **THEN** привязка MUST перейти в `ACTIVE` с указанным `vk_peer_id`, код MUST быть помечен использованным, а операция MUST вернуть успешный результат с `user_id`

#### Scenario: Регистронезависимое сопоставление

- **WHEN** передан код в нижнем регистре с окружающими пробелами
- **THEN** он MUST быть нормализован и успешно сопоставлен с сохранённым кодом

#### Scenario: Несуществующий код

- **WHEN** переданный код отсутствует в БД
- **THEN** операция MUST вернуть доменную ошибку «код недействителен» и MUST NOT изменять данные

#### Scenario: Уже использованный код

- **WHEN** у найденного кода `used_at IS NOT NULL`
- **THEN** операция MUST вернуть доменную ошибку «код уже использован» и MUST NOT изменять данные

#### Scenario: Истёкший код

- **WHEN** у найденного кода `expires_at <= now()`
- **THEN** операция MUST вернуть доменную ошибку «срок действия кода истёк» и MUST NOT изменять данные

#### Scenario: VK-аккаунт уже привязан к другому пользователю

- **WHEN** переданный `vk_peer_id` уже принадлежит другой non-deleted записи
- **THEN** операция MUST вернуть доменную ошибку конфликта, MUST NOT переносить привязку и MUST NOT помечать код использованным

#### Scenario: Повторная доставка того же подтверждения идемпотентна

- **WHEN** то же сообщение с тем же кодом обрабатывается повторно, а привязка уже `ACTIVE` с тем же `vk_peer_id`
- **THEN** операция MUST вернуть результат «уже подтверждено» без второй записи и без ошибки уровня инфраструктуры

#### Scenario: Входные данные и изменения при подтверждении

- **WHEN** вызывается доменная операция подтверждения привязки по контрольной строке
- **THEN** `vk-service` MUST предоставлять доменную операцию подтверждения, принимающую нормализованный `code` и данные VK-отправителя (`vk_peer_id`, опциональные `vk_screen_name`, `vk_display_name`). Нормализация MUST удалять окружающие пробелы и приводить код к верхнему регистру. Операция MUST проверять существование кода, `used_at IS NULL`, `expires_at > now()`, отсутствие конфликта `vk_peer_id`, после чего MUST устанавливать `vk_peer_id`, `state="ACTIVE"`, кэш имён в `user_vks` и `used_at = now()` в `vk_confirmations`.
