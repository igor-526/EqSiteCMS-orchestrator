## Why

В настоящее время создание пользователей в EqSiteCMS возможно только через прямые SQL-запросы к БД. Для масштабирования платформы и поддержки множества конюшень необходим полноценный интерфейс управления пользователями в CMS. Новая роль `USER_MANAGER` позволит администраторам конюшни самостоятельно управлять пользователями без доступа к БД, а soft-delete модель и блокировка обеспечат безопасное управление учётными записями.

## What Changes

- **Новая роль USER_MANAGER**: добавление scope `USER_MANAGER` в систему сидирования с описанием "Управление пользователями"
- **Soft-delete модель пользователей**: расширение таблицы `users` полями `is_deleted` и `deleted_at` для реализации мягкого удаления
- **Флаг блокировки**: добавление поля `is_blocked` в таблицу `users` для возможности блокировки/разблокировки пользователей
- **Backend API управления пользователями**: новые защищённые эндпоинты для CRUD операций, фильтрации, пагинации, сортировки, блокировки/разблокировки и смены пароля
- **Endpoint получения ролей**: публичный GET-эндпоинт для получения списка всех ролей (для заполнения селекторов в UI)
- **Frontend CMS страница управления пользователями**: новый раздел в боковом меню с таблицей пользователей, модальными окнами создания/редактирования, подтверждения действий

## Capabilities

### New Capabilities
- `user-management-api`: Backend API для управления пользователями — CRUD, фильтры, пагинация, сортировка, блокировка, смена пароля, endpoint получения ролей
- `user-management-ui`: Frontend CMS страница управления пользователями — таблица с фильтрами, модальные окна, действия с пользователями
- `user-soft-delete`: Soft-delete модель для пользователей с полями `is_deleted`, `deleted_at`
- `user-blocking`: Механизм блокировки пользователей с полем `is_blocked`

### Modified Capabilities
- `service-users`: Сервисный endpoint `GET /api/service/users` должен исключать заблокированных и удалённых пользователей из выдачи

## Impact

- **База данных**: миграция Alembic для добавления полей `is_deleted`, `deleted_at`, `is_blocked` в таблицу `users`
- **Backend**: новый файл `services/backend/src/api/user_management.py`, расширение `UserService`, новые схемы, обновление сидирования
- **Frontend**: новая страница `services/frontend/src/app/(protected)/users/`, компоненты таблицы и модальных окон в `src/features/`
- **Безопасность**: middleware/dependency для проверки наличия scope `USER_MANAGER` или `SUPERUSER`
- **Сервисные эндпоинты**: фильтрация удалённых/заблокированных пользователей в `GET /api/service/users`
