## Context

В EqSiteCMS существует универсальный компонент PhotoSelectorModal, который позволяет выбирать главную фотографию для сущностей. В настоящее время:

1. **Эталонные реализации**: Разделы "Услуги и цены" и "Новости" имеют полностью работающий выбор фотографий через PhotoSelectorModal
2. **Частичная реализация**: Раздел "Лошади" (вкладка "Лошади") имеет импортированный PhotoSelectorModal, но не имеет полной логики работы
3. **Лишняя логика**: Вкладки "Породы" и "Масти" имеют кнопки для работы с фотографиями, которые не используются

**Текущая архитектура**:
- Backend: Модель `photos` поддерживает только `equestrian_id` (ID лошади), нет полей `breed_id` или `coat_color_id`
- Frontend: PhotoSelectorModal принимает `selectedPhotos`, `allPhotos`, обработчики `onUpdate`, `onLoadMorePhotos`
- API: Существуют endpoints для работы с фотографиями лошадей (`/api/photos/`)

**Stakeholders**:
- Frontend агент: Реализация UI логики PhotoSelector для лошадей
- Backend агент: Проверка и очистка backend логики (при необходимости)
- Quality Gate: Проверка соответствия эталонным реализациям

## Goals / Non-Goals

**Goals:**
1. Реализовать выбор главной фотографии для лошадей через PhotoSelectorModal, идентичный эталонным реализациям
2. Удалить кнопки и логику работы с фотографиями из таблиц пород и мастей
3. Обеспечить консистентность пользовательского опыта во всех разделах CMS

**Non-Goals:**
1. Реализация фильтрации лошадей по фотографиям (будет реализовано позже)
2. Изменение API endpoints для фотографий
3. Модификация логики работы PhotoSelectorModal компонента
4. Изменения в consumer проектах (site-ad и др.)

## Decisions

### 1. Использование существующего PhotoSelectorModal без модификаций

**Решение**: Использовать существующий компонент PhotoSelectorModal "как есть" для лошадей.

**Обоснование**:
- Компонент уже проверен в двух эталонных реализациях (цены и новости)
- Минимизация изменений и рисков
- Консистентность поведения во всех разделах

**Альтернативы**:
- Создание специализированного HorsePhotoSelectorModal — отклонено из-за избыточности
- Модификация существующего компонента — отклонено, так как текущая реализация удовлетворяет требованиям

### 2. Последовательное удаление логики фотографий пород/мастей

**Решение**: Сначала реализовать функционал для лошадей, затем удалить лишнюю логику.

**Обоснование**:
- Позволяет протестировать новый функционал в изоляции
- Уменьшает риск regression bugs
- Упрощает code review

**Альтернативы**:
- Параллельные изменения — отклонено из-за сложности отладки

### 3. Очистка только frontend логики

**Решение**: Удалить только frontend код для фотографий пород/мастей, backend не трогать.

**Обоснование**:
- Модель photos уже не содержит breed_id/coat_color_id
- Backend endpoints для фотографий пород/мастей не существуют
- Минимальный scope изменений

## Risks / Trade-offs

### Risk 1: Regression в существующем функционале лошадей
**Mitigation**: 
- Тщательное тестирование после изменений
- Проверка всех связанных обработчиков событий
- Валидация через Quality Gate

### Risk 2: Неполное удаление логики пород/мастей
**Mitigation**:
- Поиск всех упоминаний `onOpenHorseBreedPhotosModal` и `onOpenHorseCoatColorPhotosModal`
- Проверка тестовых файлов на наличие ссылок
- Code review от Quality Gate агента

### Risk 3: Несогласованность состояний в horses/page.tsx
**Mitigation**:
- Следование паттернам из эталонных реализаций
- Чистка неиспользуемых состояний и обработчиков
- Проверка TypeScript типизации

## Migration Plan

### Этап 1: Реализация PhotoSelector для лошадей (Frontend агент)
1. Добавить полную логику usePhotoSelector для лошадей
2. Реализовать обработчики handleOpenHorsePhotosModal, handleUpdateHorsePhotos
3. Добавить PhotoSelectorModal в JSX с корректными пропсами
4. Протестировать функциональность

### Этап 2: Удаление логики пород/мастей (Frontend агент)
1. Удалить пропс onOpenHorseBreedPhotosModal из HorseBreedsTable
2. Удалить пропс onOpenHorseCoatColorPhotosModal из HorseCoatColorsTable
3. Удалить связанные состояния и обработчики в horses/page.tsx
4. Обновить тесты для компонентов

### Этап 3: Проверка backend (Backend агент)
1. Проверить наличие логики фотографий пород/мастей в backend
2. При наличии — удалить (маловероятно, учитывая модель данных)

### Этап 4: Quality Gate
1. Проверить соответствие эталонным реализациям
2. Запустить тесты
3. Проверить отсутствие regression
4. Валидировать удаление всей лишней логики
