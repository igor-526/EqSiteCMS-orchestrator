## Why

Тестирование сайта-потребителя «ИНЛав» (`services/site-ksk-inlove`, docs/tasks/075) выявило системную проблему: соседние секции `Section` независимо накладывают `padding-block` сверху и снизу без схлопывания (нет margin-collapse), поэтому визуальный разрыв между блоками равен **сумме** двух паддингов (120+120=240px, 160+120=280px и т.д.) вместо одного осмысленного значения — отсюда жалобы «слишком много свободного места» на главной, «Постое», «Наших лошадях» и «О клубе». Отдельно: карточки услуг («Занятия», «Постой») фильтруются на клиенте по хардкоженным спискам slug'ов и словарю категорий вместо серверной фильтрации по группе услуг; карточка новости на главной — крупная вертикальная, а не компактная горизонтальная; сетка карточек тарифов — 2 в ряд вместо 3 на десктопе; логотип имеет впечатанный белый фон; маркер активного пункта выпадающего меню смещён относительно текста; неиспользуемый (уже мёртвый в коде) блок-предупреждение о переменности цен должен быть окончательно убран из контракта компонентов; на странице «Наши лошади» дублируется заголовок и лишняя CTA-кнопка. Пользователь явно потребовал решать раскладку **переиспользуемо**, одним общим механизмом, а не точечными правками на каждой странице.

## What Changes

- Ввести в переиспользуемый `Section`-примитив (`src/ui/foundations`) механизм схлопывания отступа между смежными секциями («seam») и явный проп для обрезки паттинга на границе с header/footer (`trimBottom`/аналог), вместо суммирования независимых `padding-block`. Один CSS-механизм применяется автоматически везде, где секции идут подряд.
- Сделать `IntroSection` (сейчас жёстко `spacing="editorial"`, 160/96px) конфигурируемым по `spacing`, и добавить `EditorialSplitSection` вариант «на всю ширину» для случая без `image` (сейчас пустая колонка 7fr визуально сжимает контент в правую треть).
- Применить новую spacing-модель на главной (карточки услуг → «Новости», контакты → footer), на «Постое» (цепочка «Постой» → «Инфраструктура» → «Что входит» → «Стоимость»), на «Наших лошадях» (заголовок → сетка) и на «О клубе» (шапка → первый заголовок), сократив видимый разрыв примерно в 4 раза относительно текущего.
- Убрать дублирующий `<h2>Лошади клуба</h2>` в `HorsesGrid` и CTA-блок «Записаться…» (`HorsesCta`) со страницы `/loshadi`.
- Сделать второй текстовый блок страницы «О клубе» полноширинным вариантом `EditorialSplitSection` (без пустой image-колонки).
- Заменить крупную вертикальную карточку новости на главной компактным горизонтальным вариантом `NewsCard` на всю ширину.
- На карточках тарифов (`TariffCard`, используются на `/uslugi/zanyatiya|progulki|postoy`): сетка 3 в ряд на десктопе вместо 2; уменьшенная доля изображения на мобильной версии (замена соотношения `4:5` на менее доминирующее для mobile); полужирное (700) начертание названия тарифа; клик по изображению на десктопе ведёт на detail-страницу тарифа.
- Убрать серверную зависимость фильтрации **всех трёх** страниц услуг («Занятия» с переключателем «Разовые/Абонементы», «Прогулки», «Постой») от клиентских хардкод-списков (`LESSONS_ALLOWED_SLUGS`, `LESSON_CATEGORY`, `RIDES_NAME_QUERY`/`RIDES_ALLOWED_SLUGS`, `BOARDING_NAME_QUERY`/`BOARDING_ALLOWED_SLUGS`). Принцип, подтверждённый пользователем: «Основных услуг быть не должно. Группа = страница с услугами» — ни одна страница не обращается к catch-all группе «Основные услуги». Переключатель «Разовые/Абонементы» на странице остаётся, но выполняет **два отдельных запроса** (по одному на состояние) к соответствующим группам вместо одного repeatable `?groups=A&groups=B` с неопределённой семантикой; «Прогулки» и «Постой» запрашивают свои собственные группы. Detail-route guard проверяет принадлежность тарифа допустимым группам страницы через поле `groups` в ответе API, а не статический массив slug'ов.
- Провести идемпотентную локальную (dev-only, без stand/production) data-операцию: создать в `price_groups` четыре недостающие группы («Разовые», «Абонементы», «Прогулки», «Постой частных лошадей») **прямой SQL-записью** в локальную dev-БД (без вызова Protected Write API — endpoint назначения группы тарифу не подтверждён и не требуется) и назначить существующие тарифы в соответствующие группы. Схема БД и backend-код не меняются. Старая группа «Основные услуги» и её существующие связи остаются нетронутыми как deprecated-in-place (единственная ссылка на неё в коде сайта — `LESSONS_GROUP_NAME` — удаляется).
- Окончательно убрать из контракта `PricesSection`/`LessonsPrices`/`RidesPrices`/`BoardingPrices` неиспользуемый проп `notice`/`InlineNotice` (сам текст «Цены и условия собраны из нескольких источников…» уже не подключён в коде — это удаление мёртвой проводки и обновление design-doc источника истины).
- Добавить прозрачную копию логотипа (`inlove-logo-transparent.png`) рядом с существующим `inlove-logo.jpg` (оригинал не изменяется/не удаляется) и переключить на неё `Logo`-компонент.
- Доработать визуальное оформление группы «Услуги» в мобильном и footer-меню (`GroupedNavigation`), чтобы она читалась как группа, а не как подпись того же уровня, что и остальные пункты.
- Исправить вертикальное позиционирование маркера активного пункта выпадающего меню (`.navLink::after`), который сейчас позиционируется от низа 44px-блока, а не от центра строки текста.

## Capabilities

### New Capabilities
- `inlove-price-group-curation`: идемпотентная, обратимая, dev-local data-операция прямой SQL-записи четырёх недостающих `price_groups` («Разовые», «Абонементы», «Прогулки», «Постой частных лошадей») и назначения существующих тарифов в них — по аналогии с прецедентом `inlove-site-settings-curation`; без изменения schema, backend-кода, без вызова API и без изменения access policy.

### Modified Capabilities
- `inlove-ui-components`: контракт `Section`/`IntroSection`/`EditorialSplitSection` дополняется механизмом schlopывания смежных отступов, конфигурируемым `spacing` для `IntroSection` и full-width-вариантом `EditorialSplitSection` без image.
- `inlove-content-pages`: композиция главной (компактная горизонтальная новость, сокращённый разрыв «Услуги→Новости» и «Контакты→Footer») и `/about` (сокращённый разрыв «шапка→заголовок», полноширинный второй блок).
- `inlove-services-pages`: сетка карточек тарифов 3 в ряд на десктопе, уменьшенное mobile-изображение, полужирное название, клик по изображению на desktop, группо-ориентированная backend-фильтрация **всех трёх** страниц («Занятия»/«Прогулки»/«Постой») без клиентского allow-list и без catch-all группы «Основные услуги», удаление notice-блока из композиции, сокращённый разрыв между блоками «Постой»/«Инфраструктура»/«Что входит»/«Стоимость».
- `inlove-horses-pages`: удаление дублирующего заголовка «Лошади клуба» и CTA «Записаться…» из композиции `/loshadi`, сокращённый разрыв «заголовок→сетка».
- `inlove-site-shell`: прозрачный логотип, визуальное оформление группы «Услуги» в mobile/footer-меню, исправление позиционирования маркера активного пункта dropdown.

## Impact

- **Код:** `services/site-ksk-inlove/src/ui/foundations/**`, `src/ui/sections/**`, `src/ui/cards/**`, `src/ui/navigation/**`, `src/ui/atoms/**` (Logo), `src/features/contentPages/{home,horses,about,lessons,rides,boarding}/**`, `src/features/contentPages/services/{pricesLoaders,lessonsLoaders,boardingLoaders}.ts`, `public/images/inlove-logo.*`.
- **Design docs (источник истины, требуют явного ownership по `agents/howto/site-ksk-inlove-design.md`):** `docs/sites/inlove/scheme.md`, `docs/sites/inlove/components.md`, `docs/sites/inlove/design_system_specification.md`.
- **Данные (без кода):** таблицы `price_groups`, `price_groups_relations` в БД backend — только новые строки через прямую SQL-запись, локально/dev-only (без вызова API).
- **API:** новых endpoint'ов и изменений access policy нет — фронтенд использует существующий `GET /api/prices` (`groups` фильтр); `POST /api/prices/groups` (Protected Write, уже существует) этим change не вызывается, проверяется только регрессионно (access policy не меняется).
- **Deployment:** `services/site-ksk-inlove` остаётся вне core release scope; change не меняет и не инициирует deployment/Helm.
