## Why

Новому клиенту EqSiteCMS нужна изолированная стартовая кодовая база публичного сайта без страниц, визуального слоя, контента, ассетов и идентификаторов «Александровой дачи», но с проверенной интеграционной логикой CMS. Исходный `site-ad` нельзя использовать напрямую: его копия должна стать нейтральным каркасом `site-ksk-inlove`, а Git-репозиторий пользователь инициализирует самостоятельно.

## What Changes

- Создать `services/site-ksk-inlove` на основе состава tracked-файлов `services/site-ad`, не копируя `.git`, зависимости, build/cache artifacts и локальные секреты.
- Сохранить Next.js/App Router архитектуру исходника, обновив Next.js с `15.5.6` до patch-релиза `15.5.25`, и оставить переиспользуемый слой Public Read API, DTO, сервисы получения данных, хук/context настроек сайта и необходимую техническую observability-логику.
- Удалить маршруты и страницы исходного сайта, feature/UI-композицию, Storybook-истории, статический контент и брендовые медиа; оставить только минимальный технический app shell, необходимый для запуска и проверки проекта.
- Исключить все следы «Александровой дачи»: названия, домены, адреса, ссылки, изображения, fallback metadata и tenant-значения.
- Не переносить счётчик Яндекс Метрики, его ID и настройки вебмастера; нейтральные карты/провайдеры не считаются счётчиками и остаются только если входят в сохраняемую небрендовую логику.
- Удалить `robots.ts` и `sitemap.ts` вместе со старым SEO-контекстом; пустой `/` должен временно возвращать стандартный `404`.
- Скопировать `.helm/**` и `.github/**` побайтово без редактирования, явно пометив новый проект как неготовый к деплою до отдельной адаптации этих файлов.
- Обновить локальную идентичность runtime/configuration и документацию нового сайта, зафиксировать `inlove-stand.eqcms.ru` как согласованный stand domain без runtime fallback, не инициируя Git и не добавляя запись в `services.manifest`: remote и manifest пользователь оформит самостоятельно.
- Добавить новый сайт в централизованный каталог `SERVICES.md` как отдельный public site consumer вне core release scope.

## Capabilities

### New Capabilities

- `inlove-site-skeleton`: нейтральный запускаемый каркас `site-ksk-inlove`, правила очистки наследия `site-ad`, сохранения CMS integration layer и неизменного копирования deployment-заготовок.

### Modified Capabilities

- `site-consumer-contracts`: распространить требования Public Read client/tenant selector и запрет CMS-аутентификации на новый consumer `site-ksk-inlove` без изменения backend endpoint contract.

## Impact

- Новый сервис: `services/site-ksk-inlove/**`.
- Каталог сервисов: `SERVICES.md`; `services.manifest` остаётся без изменений до появления remote URL.
- Источник шаблона `services/site-ad/**` используется только для чтения и не изменяется.
- Backend, CMS frontend, схема БД и NATS-контракты не изменяются.
- API endpoints не добавляются и не меняются; новый consumer использует существующие Public Read `GET` и существующее публичное write-исключение callback только в сохранённом API-слое, без пользовательского UI.
- `.helm/**` и `.github/**` нового сайта намеренно сохраняют исходные значения и поэтому не подтверждают deploy readiness.
