## Context

Протокол NATS JetStream (`agents/howto/nats-jetstream-protocols.md`) описывает архитектуру, конфигурацию, DI, публикацию и потребление сообщений. В задачах 031 (NATS) и 033 (Celery/Redis) было реализовано протоколирование использования технологий. В задаче 033 появилась идея фиксировать параметры использования в README.md сервиса.

Сейчас:
- Протокол NATS не содержит правила о документировании в README.md.
- `services/backend/README.md` — не существует.
- `services/notification-service/README.md` и `services/email-service/README.md` — содержат шаблонный текст FastAPI Template без информации о NATS.

## Goals / Non-Goals

**Goals:**
- Добавить в протокол NATS JetStream правило: сервис, использующий NATS JetStream, обязан содержать в README.md секцию с таблицей streams/subjects/consumers.
- Обновить README.md трёх сервисов с актуальной информацией о NATS JetStream.

**Non-Goals:**
- Не менять код сервисов.
- Не менять API endpoints.
- Не добавлять новые NATS streams или subjects.

## Decisions

### 1. Формат секции NATS в README.md

**Решение:** Таблица с колонками Stream / Subject / Назначение / Роль сервиса.

**Альтернативы:**
- Свободный текст — сложнее поддерживать, нестандартизирован.
- YAML/JSON блок — избыточно для README.

**Обоснование:** Таблица компактна, легко читается, соответствует формату уже существующих таблиц в протоколе.

### 2. Структура README.md сервиса

**Решение:** Секция «NATS JetStream» располагается после «API» и перед «Локальная разработка». Содержит:
- Роль сервиса (Publisher / Pub/Sub / Consumer).
- Таблицу используемых streams и subjects.
- Описание: что отправляем / что принимаем.

### 3. Владелец изменений

**Решение:** Все изменения в рамках одного deliverable, так как это документация без пересечений с кодом.

## Risks / Trade-offs

- **Риск:** README.md может устареть при изменении NATS конфигурации. → **Митигация:** Правило в протоколе; Quality Gate проверяет актуальность при изменениях NATS.
- **Трейдофф:** Дублирование информации из протокола в README. → **Принято:** README — первое место, куда смотрит разработчик; протокол — подробный справочник.

## Migration Plan

Миграция не требуется — это чисто документационные изменения.
