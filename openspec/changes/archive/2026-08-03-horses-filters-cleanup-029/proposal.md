## Why

В разделе «Лошади» CMS накопились дублирующие и некорректно расположенные фильтры: селекторы «Породы», «Масти» и «Пол» продублированы одновременно в блоке с пагинацией и в шапке таблицы, а фильтры «База» и «Владельцы» вынесены отдельными селекторами, хотя для них есть колонки в таблице. Фильтр «Услуги» наоборот — рендерится как колонка с количеством, хотя логичнее вынести его в Select рядом с пагинацией. Необходимо привести все фильтры к единому правилу: если для фильтра есть колонка — фильтр живёт в шапке этой колонки; если колонки нет — отдельный Select в блоке пагинации. Параллельно нужно зафиксировать это правило в `agents/frontend.md`, чтобы агент не создавал дубли в будущем.

## What Changes

- Удалить дублирующие селекторы «Породы», «Масти» и «Пол» из блока с пагинацией (оставить только фильтры в шапке соответствующих колонок таблицы).
- Перенести фильтр «База» из отдельного селектора в блоке пагинации в шапку колонки «База» таблицы лошадей.
- Перенести фильтр «Владельцы» из отдельного селектора в блоке пагинации в шапку колонки «Владельцы» таблицы лошадей.
- Удалить колонку «Услуги» из таблицы и вынести фильтр услуг в отдельный Select в блок с пагинацией.
- Обновить `agents/frontend.md`, добавив правило: фильтры размещаются в шапке колонки таблицы, если для фильтра есть колонка; если подходящей колонки нет — отдельный Select в блоке пагинации; дублирование запрещено.
- Обеспечить корректную работу фильтров: сброс `offset` при изменении, сохранение query serialization, loading/empty/error состояния.

## Capabilities

### New Capabilities

Новые capability не вводятся.

### Modified Capabilities

- `cms-horse-ui-quality`: уточнение расположения фильтров таблицы лошадей — фильтры в шапке колонок для «База», «Владельцы», «Породы», «Масти», «Пол»; отдельный Select для «Услуги» в блоке пагинации; запрет дублирования фильтров.

## Impact

- Frontend CMS: компоненты таблицы лошадей, фильтры, блок пагинации, hook фильтрации, query serialization, тесты.
- `services/frontend` — все изменения в рамках CMS admin контура.
- `services/site-ad` не изменяется.
- `agents/frontend.md` — обновление правил размещения фильтров.
- Backend не изменяется — фильтры уже поддерживают необходимые query параметры.
