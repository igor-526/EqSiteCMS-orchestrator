## Context

В CMS раздела «Лошади» фильтры таблицы расположены несогласованно:

| Фильтр | Блок с пагинацией (HorsesHeader.tsx) | Шапка колонки таблицы (HorsesTable.tsx) |
|---|---|---|
| База (`this_stable`) | Select (строка 236) | Колонка есть, фильтра нет (строка 202) |
| Породы (`breed_ids`) | multi-Select (строка 256) | ListFilter (строка 269) — **дубль** |
| Масти (`coat_color_ids`) | multi-Select (строка 278) | ListFilter (строка 306) — **дубль** |
| Владельцы (`horse_owner_ids`) | multi-Select (строка 303) | Колонка есть, фильтра нет (строка 377) |
| Пол (`sex`) | multi-Select (строка 345) | ListFilter (строка 344) — **дубль** |
| Услуги (`services`) | Нет | ListFilter (строка 182) |

Текущее управление фильтрами: единый hook `useHorses()` в `src/features/horses/hooks/useHorses.ts` с state `horsesFilters` типа `HorseListQueryParams`. Оба компонента (`HorsesHeader` и `HorsesTable`) пишут в один state через `setHorsesFilters`, который сбрасывает `offset` в `0`.

## Goals / Non-Goals

**Goals:**
- Привести все фильтры к единому правилу: если для фильтра есть колонка таблицы — фильтр размещается в `filterDropdown` этой колонки; если колонки нет — отдельный Select в блоке с пагинацией.
- Удалить дублирующие селекторы «Породы», «Масти», «Пол» из блока пагинации.
- Добавить `filterDropdown` в колонки «База» и «Владельцы».
- Удалить колонку «Услуги» из таблицы и вынести фильтр в Select в блок пагинации.
- Зафиксировать правило в `agents/frontend.md`.

**Non-Goals:**
- Изменение backend API или query параметров.
- Изменение типа фильтров (ListFilter/StringFilter) — только перемещение.
- Миграция других разделов CMS.
- Изменение логики сортировки или пагинации.

## Decisions

### 1. Единое правило размещения фильтров

**Решение:** Фильтр размещается в `filterDropdown` колонки таблицы, если для него есть соответствующая колонка. Если подходящей колонки нет — отдельный Select в блоке с пагинацией. Дублирование запрещено.

**Альтернативы:**
- Все фильтры в шапке — отклонено, т.к. нарушает контекстную привязку фильтра к данным колонки.
- Все фильтры в блоке пагинации — отклонено, т.к. менее интуитивно для пользователей.

### 2. Удаление колонки «Услуги» из таблицы

**Решение:** Колонка «Услуги» отображает только количество связанных услуг (badge в actions column уже показывает эту информацию). Колонку удалить, а `ListFilter` по `services` вынести в Select в блок пагинации.

**Обоснование:** Количество услуг уже отображается через badge в колонке «Действия». Отдельная колонка с count дублирует информацию. Фильтр по услугам полезен, но не привязан к визуальному представлению колонки.

### 3. Добавление filterDropdown для «База» и «Владельцы»

**Решение:** Добавить `filterDropdown` с `ListFilter` в существующие колонки «База» (строка 202) и «Владелец» (строка 377) в `HorsesTable.tsx`.

**Тип фильтров:**
- «База» — `ListFilter` с опциями `THIS_STABLE_OPTIONS` (Все/Наши/Чужие), single select.
- «Владельцы» — `ListFilter` с опциями `ownerFilterOptions` из hook, multi-select.

### 4. Сохранение совместимости hook

**Решение:** Hook `useHorses()` не изменяется. Все фильтры продолжают использовать `setHorsesFilters` с автоматическим сбросом `offset`. Тип `HorseListQueryParams` уже содержит все необходимые поля.

## Risks / Trade-offs

- **[Риск]** Пользователи привыкли к текущему расположению фильтров. → **Митигация:** Фильтры в колонках — стандартный паттерн AntD, более интуитивный.
- **[Риск]** Удаление колонки «Услуги» может скрыть информацию о количестве. → **Митигация:** Badge в actions column уже показывает count.
- **[Риск]** Изменение `agents/frontend.md` может конфликтовать с другими изменениями. → **Митигация:** Правило добавляется, а не заменяет существующие.
