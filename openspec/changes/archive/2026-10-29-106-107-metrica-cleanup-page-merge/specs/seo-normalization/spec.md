# Ретроактивная нормализация страниц

## MODIFIED Requirements

### Requirement: Отсутствие ретроактивного применения настроек
PATCH и DELETE элементов черного списка SHALL влиять только на последующие входные значения, без ретроактивного разъединения. Добавление нового элемента через POST SHALL дополнительно запускать асинхронное объединение исторических страниц своей конюшни. Исходные страницы MUST сохраняться до безопасного результата Метрики; канонический UUID SHALL совпадать с последующим resolve.

#### Scenario: Добавление параметра после сохранения страницы
- **WHEN** страница `"/a?utm_source=1"` уже сохранена, затем в черный список добавлен `utm_source`, и снова разрешается `"/a?utm_source=1"`
- **THEN** resolve возвращает UUID `"/a"` (найденной или созданной страницы), старая страница временно сохраняется до merge её статистик и удаляется только после подтверждения

## ADDED Requirements

### Requirement: Ревизии и канонические соответствия
Нормализация SHALL планироваться последовательными ревизиями конюшни с устойчивым отображением source→target. Resolve и планирование MUST согласовывать одну актуальную ревизию; устаревший результат MUST NOT удалять цель последующей ревизии. После слияния повторный resolve MUST NOT воссоздавать удалённый исходный UUID.

#### Scenario: SN-01 Новый хеш и несколько параметров
- **WHEN** последовательно добавлены query-параметр и хеш, а resolve выполняется параллельно
- **THEN** используются существующие правила PageNormalizer без нового толкования URL, каждая историческая страница входит в ограниченный scan, ревизии сериализуются, транзитивные соответствия приводят к одной актуальной цели

#### Scenario: SN-02 Без коллизии и отсутствующая цель
- **WHEN** новый нормализованный путь отличается от старого, но целевая страница ещё отсутствует
- **THEN** целевой UUID создаётся обычным resolve, статистика переносится даже для единственного source; при неизменившемся пути лишняя операция не создаётся

#### Scenario: SN-03 PATCH и DELETE после POST
- **WHEN** пока merge ревизии R идёт, правило изменено или удалено
- **THEN** текущий merge использует зафиксированный снимок R, новая настройка применяется будущим resolve; утраченные после объединения варианты и исторические распределения не восстанавливаются

### Requirement: Доступ к разрешению страниц при merge
Resolve SHALL сохранять private peer policy: selector — identity hint, не auth. Internal Trusted Network Write является явным исключением для парсера, production isolation обязательна. Изменение нормализации MUST NOT открывать endpoint сайтам.


#### Scenario: SN-04 Парные resolve tests
- **WHEN** resolve вызывается без credentials и с Cookie/Bearer для двух разных tenant, а также без/с invalid selector
- **THEN** соблюдается matrix, нормализация и aliases изолированы tenant, отсутствующий selector не подменяется правами сессии
