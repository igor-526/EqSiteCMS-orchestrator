# Жизненный цикл UUID при фоновом merge

## MODIFIED Requirements

### Requirement: Отсутствие изменения и удаления сущностей
seo-service MUST NOT предоставлять пользовательский API изменения или удаления поисковых запросов и страниц. Вне подтверждённого фонового merge запись SHALL сохранять UUID и нормализованное значение. После merge SHALL допускаться внутреннее удаление исходных страниц с сохранением канонической цели и устойчивого UUID redirect; поисковые запросы этим исключением не затрагиваются.

#### Scenario: Попытка удаления
- **WHEN** caller вызывает `DELETE /api/search-queries/{id}` или `PATCH /api/pages/{id}`
- **THEN** маршрут не существует, запись не меняется

#### Scenario: ER-01 Фоновая финализация
- **WHEN** подтверждено безопасное объединение статистик исходной страницы
- **THEN** внутренний worker удаляет исходную страницу, канонический UUID остаётся, повторный результат не удаляет цель и не воскрешает старый UUID; новых HTTP endpoints нет
