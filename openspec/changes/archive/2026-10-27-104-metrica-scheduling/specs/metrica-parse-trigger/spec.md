# Spec Delta

## MODIFIED Requirements

### Requirement: Привязка счётчика проверяется при постановке

При обработке команды парсинга из NATS (`commands.parse.ya_metrica.run`) сервис SHALL получить привязку счётчика конюшни из yandex-service (`GET /api/connections/metrica/{equestrian_id}`) и сохранить `counter_id` и `yandex_account_id` в задания. Отсутствие привязки SHALL завершаться ack с warning, недоступность yandex-service — nak (повтор до `max_deliver`); задания в обоих случаях не создаются.

#### Scenario: Счётчик не привязан
- **WHEN** yandex-service возвращает `{"counter": null}`
- **THEN** команда подтверждена (ack), в логе warning «счётчик не привязан», задания не созданы

#### Scenario: yandex-service недоступен
- **WHEN** запрос к yandex-service завершился таймаутом, транспортной ошибкой или не-2xx
- **THEN** сообщение получает nak и доставляется повторно, задания не созданы, лог без URL и тела ответа

### Requirement: Явный диапазон дат с обрезкой

Если переданы обе даты, сервис SHALL обрезать диапазон до границ `[сегодня − 2 года; сегодня]` и ставить в очередь обрезанный диапазон для обоих видов. Если после обрезки диапазон пуст (`date_from > date_to`, в том числе исходно перевёрнутый) либо передана только одна дата, команда SHALL отклоняться (ack с warning «некорректный диапазон дат») без создания заданий. Факт обрезки SHALL отражаться в логе и в сохранённом признаке `clamped` запуска.

#### Scenario: Обрезка верхней границы
- **WHEN** сегодня `2026-10-26`, а передан `2026-10-20..2026-10-31`
- **THEN** задания поставлены за `2026-10-20..2026-10-26`, `clamped=true`

#### Scenario: Обрезка нижней границы
- **WHEN** сегодня `2026-10-26`, а передан `2023-01-01..2024-11-03`
- **THEN** задания поставлены за `2024-10-26..2024-11-03`, `clamped=true`

#### Scenario: Диапазон без обрезки
- **WHEN** передан `2026-10-21..2026-10-25`
- **THEN** задания поставлены за этот диапазон, `clamped=false`

#### Scenario: После обрезки ничего не осталось
- **WHEN** сегодня `2026-10-26`, а передан `2026-10-27..2026-10-31` либо `2020-01-01..2023-12-31`
- **THEN** команда отклонена (ack, warning), задания не созданы

#### Scenario: Перевёрнутый диапазон
- **WHEN** `date_from=2026-10-25`, `date_to=2026-10-21`
- **THEN** команда отклонена (ack, warning), задания не созданы

#### Scenario: Только одна дата
- **WHEN** передан только `date_from`
- **THEN** команда отклонена (ack, warning)

### Requirement: Автоматический резолв диапазона

Если обе даты не переданы, сервис SHALL резолвить диапазон отдельно для каждого вида: `date_to` — сегодня; `date_from` — последняя записанная дата статистики конюшни этого вида включительно, но не раньше сегодняшней даты минус 2 года; при отсутствии записей — сегодня минус 2 года.

#### Scenario: Есть записанная статистика
- **WHEN** сегодня `2026-10-26`, последняя дата страниц `2026-10-25`, последняя дата запросов `2026-10-20`
- **THEN** страницы ставятся за `2026-10-25..2026-10-26`, запросы — за `2026-10-20..2026-10-26`

#### Scenario: Статистики нет
- **WHEN** у конюшни нет ни одной строки статистики и сегодня `2026-10-26`
- **THEN** оба вида ставятся за `2024-10-26..2026-10-26`

#### Scenario: Последняя запись старше двух лет
- **WHEN** последняя дата страниц `2023-01-01`, сегодня `2026-10-26`
- **THEN** страницы ставятся за `2024-10-26..2026-10-26`

#### Scenario: Ежедневный запуск по расписанию
- **WHEN** сегодня `2026-10-27`, последняя дата страниц и запросов `2026-10-26`, пришла команда `window=auto`
- **THEN** оба вида ставятся за `2026-10-26..2026-10-27` (2 дня: вчерашние данные обновляются, сегодняшние добавляются)

### Requirement: Отказ при активном запуске

Если у конюшни есть задания `queued` или `running`, обработка команды SHALL завершаться ack (info «парсинг уже выполняется») без создания заданий.

#### Scenario: Повторный вызов во время парсинга
- **WHEN** предыдущий запуск конюшни ещё имеет задания `queued`
- **THEN** команда подтверждена, количество заданий не меняется


## REMOVED Requirements

### Requirement: Endpoint постановки парсинга
**Reason**: Постановка парсинга — ответственность seo-service через NATS; HTTP-вход у ya-metrica-service исключён, чтобы backend и другие caller'ы не обходили оркестратор.
**Migration**: Использовать `POST /api/seo/parse-jobs` (backend) либо `POST /api/parse-jobs` (seo-service); сервис метрики принимает только команду `commands.parse.ya_metrica.run` (`metrica-parse-command-consumer`).

### Requirement: Access-контракт endpoint запуска
**Reason**: Endpoint M2 `POST /api/metrica/stats/parse` удалён: Private Peer Write exception больше не существует; запрос к этому пути обслуживается как неизвестный маршрут (framework rejection R1, `400`).
**Migration**: Матрица доступа новых операций — `seo-parse-trigger-api`, `parse-job-messaging`; M1/H1 не меняются.
