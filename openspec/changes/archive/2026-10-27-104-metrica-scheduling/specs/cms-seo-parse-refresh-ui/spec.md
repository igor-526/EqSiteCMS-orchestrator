# Spec Delta

## Purpose

Кнопка ручного обновления статистики Яндекс.Метрики на вкладках «Страницы» и «Запросы» SEO-раздела CMS с модалкой подтверждения. После подтверждения backend ставит задачу через seo-service; CMS desktop-only, эталон 1366×768.

## ADDED Requirements

### Requirement: Кнопка обновления на «Страницах» и «Запросах»
Вкладки «Страницы» и «Запросы» SHALL показывать кнопку «Обновить данные» в блоке управления шапки рядом с пагинатором и «Сбросить»; на вкладках «Яндекс.Метрика» и «Яндекс.Вебмастер» кнопки нет. Кнопка MUST иметь доступное имя, быть доступной с клавиатуры и не перекрывать соседние элементы на 1366×768.

#### Scenario: Кнопка на двух вкладках
- **WHEN** ADMIN открывает вкладки «Страницы» и «Запросы»
- **THEN** кнопка «Обновить данные» видна в каждой, на остальных вкладках отсутствует

#### Scenario: Раскладка 1366×768
- **WHEN** страница открыта в viewport 1366×768
- **THEN** кнопка, пагинатор, «Сбросить» и «Нормализация» не перекрываются и не выходят за область заголовка

### Requirement: Модалка подтверждения перед запуском
Нажатие кнопки SHALL открывать модалку подтверждения с заголовком, пояснением (данные Метрики будут загружены в фоне за последние дни, таблица не обновляется мгновенно) и кнопками «Подтвердить»/«Отмена»; запрос на backend MUST отправляться только после подтверждения. Закрытие модалки (Esc, крестик, «Отмена») MUST NOT отправлять запрос.

#### Scenario: Отмена
- **WHEN** ADMIN нажимает кнопку, затем «Отмена» либо Esc
- **THEN** запросов к API нет, модалка закрыта, фокус возвращается на кнопку

#### Scenario: Подтверждение
- **WHEN** ADMIN нажимает «Подтвердить»
- **THEN** отправляется ровно один `POST /seo/parse-jobs` с `{"provider":"ya_metrica"}`, пока запрос идёт, модалка не закрывается, кнопки заблокированы

### Requirement: Результат запуска и ошибки
Успех (`202`) SHALL закрывать модалку и показывать уведомление «Обновление поставлено в очередь». Ошибка SHALL оставлять модалку открытой с безопасным сообщением: `400` — показ `detail` backend, `401` — штатный auth-flow, `403` — «Недостаточно прав», `502`/`503`/сеть — «Не удалось поставить задачу, повторите позже». POST MUST NOT повторяться автоматически; таблица MUST NOT перечитываться автоматически.

#### Scenario: Успех
- **WHEN** backend отвечает `202`
- **THEN** модалка закрыта, показано уведомление, повторный POST не отправлялся, таблица не перезапрошена

#### Scenario: Счётчик не привязан
- **WHEN** backend отвечает `400` с `detail`
- **THEN** модалка остаётся открытой, сообщение показано внутри, кнопка «Подтвердить» снова доступна

#### Scenario: Сбой очереди
- **WHEN** backend отвечает `503` или сеть недоступна
- **THEN** показано общее безопасное сообщение без тела ответа, повтор — только по явному нажатию

### Requirement: Доступ и защита от повторов
Действие SHALL требовать актуальный `ADMIN` без наследования ролей; без права кнопка и запрос недоступны (страница SEO и так закрыта для не-ADMIN). Hook MUST иметь синхронную защиту от повторного submit и guard перед вызовом API; в pending закрытие модалки и смена вкладки не отправляют второй запрос.

#### Scenario: Двойное подтверждение
- **WHEN** пользователь дважды быстро нажимает «Подтвердить»
- **THEN** отправляется один запрос

#### Scenario: Отзыв прав
- **WHEN** ADMIN отозван после отрисовки кнопки
- **THEN** hook не вызывает API, модалка не открывается

### Requirement: Повторное использование модалки подтверждения
Подтверждение SHALL использовать общий `ConfirmActionModal` с обратно совместимыми необязательными свойствами текста и стиля кнопки подтверждения; существующая модалка отвязки счётчика MUST сохранить поведение и вид. Для запуска обновления кнопка подтверждения MUST быть не «danger».

#### Scenario: Регрессия отвязки
- **WHEN** открывается подтверждение «Отвязать счётчик?»
- **THEN** текст кнопки «Подтвердить» и danger-стиль не изменились

### Requirement: Access matrix потребляемого API
CMS SHALL вызывать только backend (не seo-service и не ya-metrica-service); tenant — из сессии, без selector из браузера.

#### Scenario: Контракт новой операции
- **WHEN** API-boundary тест вызывает операцию без сессии, с ADMIN и с другими ролями
- **THEN** фактические статусы соответствуют матрице

| method | path | access class | roles | expected without auth | expected with auth |
|---|---|---|---|---|---|
| POST | `/api/seo/parse-jobs` | Protected Write | только ADMIN | `401` (штатный refresh/login flow) | `202`; без ADMIN `403`; невалидное тело/нет привязки `400`; downstream `502`; очередь `503` |
