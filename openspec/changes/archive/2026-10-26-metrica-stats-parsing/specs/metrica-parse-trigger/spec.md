# Spec Delta

## Purpose

Сервисный endpoint ya-metrica-service для постановки парсинга статистики Яндекс.Метрики конюшни в очередь: входной контракт, резолв диапазона дат, безопасные ошибки и access-контракт service-to-service.

## ADDED Requirements

### Requirement: Endpoint постановки парсинга

ya-metrica-service SHALL принимать `POST /api/metrica/stats/parse` с JSON `{"equestrian_id": UUID, "date_from": "YYYY-MM-DD" | null, "date_to": "YYYY-MM-DD" | null}`; лишние поля запрещены. Успешная постановка SHALL возвращать `200` с `run_id`, `equestrian_id`, режимом дат (`explicit`/`auto`), признаком `clamped`, резолвленными диапазонами по видам и списком созданных заданий (`id`, `kind`, `date_from`, `date_to`, `sequence`, `status=queued`).

#### Scenario: Постановка с явным диапазоном
- **WHEN** доверенный сервис отправляет `{"equestrian_id": E, "date_from": "2026-10-21", "date_to": "2026-10-25"}` для конюшни с привязанным счётчиком
- **THEN** ответ `200` содержит `date_mode=explicit`, по одному заданию `pages` и `search_queries` за `2026-10-21..2026-10-25` в статусе `queued`

#### Scenario: Ответ не содержит секретов
- **WHEN** постановка успешна
- **THEN** ответ не содержит токен, ciphertext, ID аккаунта Яндекса и данные профиля Яндекса

### Requirement: Привязка счётчика проверяется при постановке

Перед созданием заданий сервис SHALL получить привязку счётчика конюшни из yandex-service (`GET /api/connections/metrica/{equestrian_id}`) и сохранить `counter_id` и `yandex_account_id` в задания. Отсутствие привязки или недоступность yandex-service SHALL давать `400` без создания заданий.

#### Scenario: Счётчик не привязан
- **WHEN** yandex-service возвращает `{"counter": null}`
- **THEN** ответ `400` с `detail="Счётчик Яндекс.Метрики не привязан к конюшне"`, задания не созданы

#### Scenario: yandex-service недоступен
- **WHEN** запрос к yandex-service завершился таймаутом, транспортной ошибкой или не-2xx
- **THEN** ответ `400` с `detail="Не удалось получить данные интеграции Яндекс"`, задания не созданы

### Requirement: Сегодняшняя дата по смещению от UTC

«Сегодня» SHALL вычисляться как дата текущего момента UTC, сдвинутого на целое число часов из настройки `YA_METRICA_UTC_OFFSET_HOURS` (по умолчанию `3`, допустимо `-12..14`). Значение вне диапазона или нецелое MUST отклоняться при загрузке конфигурации.

#### Scenario: Переход суток по смещению
- **WHEN** сейчас `2026-10-26T22:30Z`, а смещение `3`
- **THEN** сегодняшней датой считается `2026-10-27`

#### Scenario: Некорректное смещение
- **WHEN** `YA_METRICA_UTC_OFFSET_HOURS=15` либо `3.5`
- **THEN** загрузка конфигурации отклоняется до обслуживания запросов

### Requirement: Явный диапазон дат с обрезкой

Если переданы обе даты, сервис SHALL обрезать диапазон до границ `[сегодня − 2 года; сегодня]` и ставить в очередь обрезанный диапазон для обоих видов. Если после обрезки диапазон пуст (`date_from > date_to`, в том числе исходно перевёрнутый) либо передана только одна дата, ответ SHALL быть `400` с `detail="Некорректный диапазон дат"`. Факт обрезки SHALL отражаться в ответе и логе.

#### Scenario: Обрезка верхней границы
- **WHEN** сегодня `2026-10-26`, а передан `2026-10-20..2026-10-31`
- **THEN** ответ `200`, задания поставлены за `2026-10-20..2026-10-26`, `clamped=true`

#### Scenario: Обрезка нижней границы
- **WHEN** сегодня `2026-10-26`, а передан `2023-01-01..2024-11-03`
- **THEN** ответ `200`, задания поставлены за `2024-10-26..2024-11-03`, `clamped=true`

#### Scenario: Диапазон без обрезки
- **WHEN** передан `2026-10-21..2026-10-25`
- **THEN** задания поставлены за этот диапазон, `clamped=false`

#### Scenario: После обрезки ничего не осталось
- **WHEN** сегодня `2026-10-26`, а передан `2026-10-27..2026-10-31` либо `2020-01-01..2023-12-31`
- **THEN** ответ `400`, задания не созданы

#### Scenario: Перевёрнутый диапазон
- **WHEN** `date_from=2026-10-25`, `date_to=2026-10-21`
- **THEN** ответ `400`, задания не созданы

#### Scenario: Только одна дата
- **WHEN** передан только `date_from`
- **THEN** ответ `400`

### Requirement: Автоматический резолв диапазона

Если обе даты не переданы, сервис SHALL резолвить диапазон отдельно для каждого вида: `date_to` — сегодня; `date_from` — последняя записанная дата статистики конюшни этого вида включительно, но не раньше сегодняшней даты минус 2 года; при отсутствии записей — сегодня минус 2 года.

#### Scenario: Есть записанная статистика
- **WHEN** сегодня `2026-10-26`, последняя дата страниц `2026-10-25`, последняя дата запросов `2026-10-20`
- **THEN** страницы ставятся за `2026-10-25..2026-10-26`, запросы — за `2026-10-20..2026-10-26`

#### Scenario: Статистики нет
- **WHEN** у конюшни нет ни одной строки статистики и сегодня `2026-10-26`
- **THEN** оба вида ставятся за `2024-10-26..2026-10-26`

#### Scenario: Последняя запись старше двух лет
- **WHEN** последняя дата страниц `2023-01-01`, сегодня `2026-10-26`
- **THEN** страницы ставятся за `2024-10-26..2026-10-26`

### Requirement: Отказ при активном запуске

Если у конюшни есть задания `queued` или `running`, endpoint SHALL отвечать `400` с `detail="Парсинг конюшни уже выполняется"` без создания заданий.

#### Scenario: Повторный вызов во время парсинга
- **WHEN** предыдущий запуск конюшни ещё имеет задания `queued`
- **THEN** ответ `400`, количество заданий не меняется

### Requirement: Access-контракт endpoint запуска

Endpoint SHALL быть явным исключением Private Peer Write (service-to-service внутри доверенной сети, без пользовательской авторизации; причина: инициатор — внутренний сервис, механизма сервисной аутентификации у peers нет, действует dev-допущение Q2 и production gate `yandex-peer-http-contract`). Cookie/Authorization MUST NOT менять результат. `equestrian_id` — идентификатор ресурса, не tenant selector: ошибки SHALL давать `400`, а не `401`.

#### Scenario: Матрица доступа
- **WHEN** Quality Gate сверяет endpoint'ы ya-metrica-service, затронутые change, по строкам матрицы ниже
- **THEN** фактические статусы без auth и с auth совпадают с матрицей, а M1/H1 не меняются

| ID | method | path | access class | roles | expected without auth | expected with auth |
|---|---|---|---|---|---|---|
| M2 | POST | ya-metrica `/api/metrica/stats/parse` | Private Peer Write exception (service-to-service) | доверенный внутренний сервис (оператор, будущий SEO-триггер); роли CMS не проверяются | `200` с запуском; validation / диапазон / нет привязки / активный запуск / yandex-service недоступен → `400` | то же; Cookie/Authorization игнорируются |
| M1 | GET | ya-metrica `/api/metrica/counters` | Sensitive Private Peer Read exception (без изменений) | доверенный внутренний caller | `200`; ошибки `400` | то же |
| H1 | GET | ya-metrica `/health` | Public Read (без изменений) | любой | `200` | то же |

#### Scenario: Anonymous вызов
- **WHEN** валидный запрос постановки отправлен без Cookie и Authorization
- **THEN** ответ `200` с запуском

#### Scenario: Вызов с пользовательскими заголовками
- **WHEN** тот же запрос отправлен с произвольными Cookie и `Authorization: Bearer ...`
- **THEN** результат идентичен anonymous вызову, заголовки не дают и не отнимают прав

#### Scenario: Невалидный вход без отражения
- **WHEN** `equestrian_id` отсутствует или не UUID, дата не в формате ISO либо есть лишнее поле
- **THEN** ответ `400` с безопасным `detail` без отражения входных значений, задания не созданы
