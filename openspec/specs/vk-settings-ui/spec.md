# vk-settings-ui Specification

## Purpose
Карточка «VK для уведомлений» в CMS-разделе «Уведомления»: состояния привязки, контрольная строка, внешние ссылки в новых вкладках, отвязка, тесты и manual QA.

## Requirements

### Requirement: Карточка VK в разделе «Уведомления»

CMS MUST добавить карточку «VK для уведомлений» на вкладку «Настройки» страницы `/notifications`, размещённую после карточки email и до карточки событий. Карточка MUST быть доступна каждому authenticated пользователю независимо от scopes; anonymous пользователь MUST блокироваться существующим auth guard.

#### Scenario: Authenticated доступ

- **WHEN** authenticated пользователь с любым набором scopes открывает вкладку «Настройки»
- **THEN** он MUST видеть карточку «VK для уведомлений»

#### Scenario: Anonymous доступ

- **WHEN** anonymous пользователь открывает `/notifications`
- **THEN** CMS MUST перенаправить или заблокировать его по существующему protected-route contract

#### Scenario: Порядок карточек

- **WHEN** отрисована вкладка «Настройки»
- **THEN** порядок карточек MUST быть: email, VK, события

### Requirement: Состояния привязки VK в UI

Карточка MUST различать пять состояний и показывать для каждого корректный контент: загрузка, «не привязан» (`404` от `GET /api/vks/me`), «ожидает подтверждения» (`state = PENDING`), «привязан» (`state = ACTIVE`), «бот заблокирован» (`state = BLOCKED`). Ошибка загрузки MUST показываться отдельным alert и MUST NOT подменяться состоянием «не привязан».

#### Scenario: Загрузка

- **WHEN** запрос состояния привязки выполняется
- **THEN** карточка MUST показывать skeleton и MUST NOT показывать кнопки действий

#### Scenario: VK не привязан

- **WHEN** backend возвращает `404`
- **THEN** карточка MUST объяснить, зачем нужна привязка, и показать единственное действие «Привязать»; инструкция, контрольная строка, ссылка на диалог и кнопка «Отвязать» MUST отсутствовать до нажатия

#### Scenario: Код выдан, привязка ещё не подтверждена

- **WHEN** пользователь нажал «Привязать» и backend вернул код
- **THEN** карточка MUST показать инструкцию, контрольную строку со сроком действия, ссылку на диалог с ботом и кнопку «Обновить код»

#### Scenario: Ожидает подтверждения

- **WHEN** `state = PENDING`
- **THEN** карточка MUST показать инструкцию, контрольную строку со сроком действия (либо предложение обновить код, если он не показан), ссылку на диалог и кнопки «Обновить код» и «Отвязать»

#### Scenario: VK привязан

- **WHEN** `state = ACTIVE`
- **THEN** карточка MUST показать признак подтверждённой привязки обычным основным цветом, отображаемое имя или `vk_screen_name`, если они переданы, и кнопку «Отвязать»; блок с кодом MUST отсутствовать

#### Scenario: Бот заблокирован

- **WHEN** `state = BLOCKED`
- **THEN** карточка MUST показать предупреждение красным о том, что сообщения от группы запрещены и уведомления не доставляются, инструкцию разрешить сообщения в диалоге, ссылку на диалог и кнопку «Отвязать»; кнопки «Привязать» и «Обновить код» MUST отсутствовать

#### Scenario: Ошибка загрузки состояния

- **WHEN** backend возвращает `502` или сеть недоступна
- **THEN** карточка MUST показать alert с понятным текстом и MUST NOT утверждать, что VK не привязан

### Requirement: Инструкция и контрольная строка

Инструкция MUST появляться только после того, как пользователь запросил привязку: в состоянии «не привязан» без выданного кода карточка MUST NOT показывать ни инструкцию, ни ссылку на диалог, чтобы не нагружать пользователя шагами, которые ему ещё не нужны. Как только код выдан либо `state = PENDING`, карточка MUST показывать инструкцию: открыть диалог с ботом группы, отправить сообщение вида `<команда> <код>`, дождаться ответа бота. Контрольная строка MUST отображаться моноширинным шрифтом с кнопкой копирования в буфер обмена, копирующей полную строку команды вместе с кодом. Рядом MUST отображаться время истечения кода.

#### Scenario: До запроса привязки инструкции нет

- **WHEN** карточка отрисована в состоянии «не привязан» и код ещё не выдан
- **THEN** инструкция и ссылка на диалог MUST отсутствовать

#### Scenario: Копирование команды

- **WHEN** пользователь нажимает кнопку копирования
- **THEN** в буфер обмена MUST попасть полная строка `<link_command> <code>`, а UI MUST показать подтверждение копирования

#### Scenario: Отображение срока действия

- **WHEN** код выдан с `expires_at`
- **THEN** карточка MUST показать срок действия в человекочитаемом виде

#### Scenario: Код истёк

- **WHEN** `expires_at` уже прошёл
- **THEN** карточка MUST пометить код недействительным и предложить обновить его

#### Scenario: Копирование недоступно

- **WHEN** Clipboard API недоступен в браузере
- **THEN** код MUST оставаться выделяемым текстом, а ошибка копирования MUST показываться без падения интерфейса

### Requirement: Внешняя ссылка на диалог с ботом

Карточка MUST показывать единственную внешнюю ссылку — на диалог с ботом (`dialog_url`), полученную из `GET /api/vks/bot-info`. Ссылка MUST открываться в новой вкладке с `target="_blank"` и `rel="noopener noreferrer"`. Ссылка на страницу сообщества (`group_url`) MUST NOT отображаться: привязка выполняется в личном диалоге, а переход в сообщество уводит пользователя от сценария. Ссылка на диалог SHOULD вести пользователя сразу в переписку с ботом; предзаполнение текста сообщения MUST NOT считаться обязательным, поскольку VK не поддерживает подстановку текста в ссылку на диалог.

#### Scenario: Атрибуты ссылки

- **WHEN** отрисована ссылка на диалог
- **THEN** она MUST иметь `target="_blank"` и `rel="noopener noreferrer"`

#### Scenario: Ссылка на сообщество отсутствует

- **WHEN** карточка отрисована в любом состоянии
- **THEN** ссылка на `group_url` MUST отсутствовать

#### Scenario: Источник ссылки

- **WHEN** карточка отрисована
- **THEN** адрес ссылки MUST приходить из `GET /api/vks/bot-info` и MUST NOT быть захардкожен в компоненте

#### Scenario: Данные бота недоступны

- **WHEN** `GET /api/vks/bot-info` возвращает `503` или ошибку
- **THEN** карточка MUST показать сообщение о незавершённой настройке VK, скрыть ссылку на диалог и MUST NOT блокировать остальные карточки страницы

### Requirement: Действия карточки VK

Карточка MUST предоставлять ровно два действия: «Привязать» / «Обновить код» (`POST /api/vks/issue-confirmation`) и «Отвязать» (`DELETE /api/vks/{user_id}`). В состоянии «не привязан» без выданного кода кнопка MUST называться «Привязать»; после выдачи кода и в состоянии `PENDING` — «Обновить код». Отвязка MUST требовать подтверждения в модальном окне, текст которого сообщает, что для повторной привязки понадобится новый код. Все мутации MUST выполняться только через основной backend.

#### Scenario: Запуск привязки

- **WHEN** пользователь без привязки нажимает «Привязать»
- **THEN** UI MUST выполнить запрос выдачи, после успешного ответа показать инструкцию, код и ссылку на диалог и перезапросить состояние привязки

#### Scenario: Обновление кода

- **WHEN** пользователь в состоянии `PENDING` нажимает «Обновить код»
- **THEN** UI MUST показать новый код, а предыдущий MUST перестать отображаться

#### Scenario: Модальное окно отвязки

- **WHEN** пользователь нажимает «Отвязать»
- **THEN** MUST открыться модальное окно подтверждения с предупреждением о необходимости новой привязки

#### Scenario: Успешная отвязка

- **WHEN** отвязка подтверждена и backend вернул `204`
- **THEN** модальное окно MUST закрыться, MUST появиться уведомление об успехе, а карточка MUST перейти в состояние «не привязан»

#### Scenario: Ошибка мутации

- **WHEN** запрос выдачи кода или отвязки возвращает ошибку
- **THEN** UI MUST показать понятное сообщение, сохранить текущее состояние карточки и MUST NOT закрывать открытое модальное окно

#### Scenario: Конфликт состояния при выдаче

- **WHEN** backend возвращает `409` из-за состояния `ACTIVE` или `BLOCKED`
- **THEN** UI MUST показать доменное сообщение и перезапросить состояние привязки

### Requirement: Защита от повторной отправки

Кнопки карточки VK MUST переходить в pending-состояние на время запроса и MUST блокировать повторную отправку. Визуальное состояние карточки MUST меняться только после успешного ответа backend.

#### Scenario: Двойной клик по получению кода

- **WHEN** пользователь дважды быстро нажимает «Привязать»
- **THEN** MUST быть отправлен ровно один запрос

#### Scenario: Отсутствие оптимистичного обновления

- **WHEN** запрос отвязки завершается ошибкой
- **THEN** карточка MUST сохранить предыдущее состояние привязки

### Requirement: Слой доступа к VK API во frontend

CMS MUST добавить `src/api/vk.ts` с функциями `getMyVkBinding`, `getVkBotInfo`, `issueVkConfirmation`, `deleteVkBinding`, типы в `src/types/api/notifications.ts` (`VkBindingOutDto`, `VkBotInfoOutDto`, `VkIssueConfirmationOutDto`) и функции сервисного слоя в `src/features/notifications/services/notificationService.ts`. Архитектура MUST соблюдать цепочку `page → feature UI → hook → service → src/api`. CMS MUST NOT обращаться к приватным сервисам напрямую и MUST NOT импортировать код `site-*`.

#### Scenario: Соблюдение цепочки слоёв

- **WHEN** выполняются architecture checks
- **THEN** компоненты карточки VK MUST NOT вызывать `fetch` напрямую, а обращения к API MUST идти через hook → service → `src/api`

#### Scenario: Отсутствие обращений к приватным сервисам

- **WHEN** выполняется поиск адресов приватных сервисов по `services/frontend/src`
- **THEN** совпадений MUST NOT быть; все VK-запросы MUST идти на `/api/vks/*`

### Requirement: Тесты карточки VK

Frontend MUST покрыть карточку unit/component тестами с mocks/MSW без live backend. Покрытие MUST включать: все пять состояний, скрытость инструкции и ссылки до запроса привязки, отсутствие ссылки на сообщество, ошибку загрузки, выдачу и обновление кода, копирование команды, атрибуты ссылки на диалог, недоступность `bot-info`, модальное окно отвязки с успехом и ошибкой, `401`/`403`/`409`/`502`, защиту от двойной отправки.

#### Scenario: Automated coverage

- **WHEN** feature готова к Quality Gate
- **THEN** тесты MUST покрывать все перечисленные случаи и проходить без реального backend

#### Scenario: Проверка атрибутов ссылки в тестах

- **WHEN** выполняется component-тест карточки в состоянии с видимой ссылкой на диалог
- **THEN** тест MUST утверждать наличие `target="_blank"` и `rel="noopener noreferrer"`, а также отсутствие ссылки на сообщество

### Requirement: Manual QA карточки VK

Исполнитель MUST проверить карточку в реальном браузере на desktop, tablet и mobile и сохранить итоговый passed/failed отчёт. Проверка MUST охватывать все состояния, копирование кода, открытие ссылок в новых вкладках, модальное окно отвязки и ошибочные ответы backend.

#### Scenario: Responsive и error QA

- **WHEN** QA проходит состояния карточки, копирование, ссылки, модальное окно и ошибки backend
- **THEN** layout MUST не иметь overlap и обрезки на всех трёх ширинах, модальное окно MUST сохранять состояние после ошибки, а failed-кейсы MUST содержать screenshots и network status/body

#### Scenario: Проверка длинного кода и имени

- **WHEN** отображаются код максимальной длины и длинное отображаемое имя VK
- **THEN** текст MUST переноситься или обрезаться без выхода за границы карточки
