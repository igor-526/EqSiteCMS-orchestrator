# Service Endpoint Pagination

## Purpose

Спецификация стандартизированной пагинации для сервисных эндпоинтов EqSiteCMS через параметры `limit` и `offset`.

## Requirements

### Requirement: Стандартизация пагинации сервисных эндпоинтов
Все сервисные эндпоинты, возвращающие списки, MUST использовать пагинацию через параметры `limit` и `offset`. Ответ MUST использовать формат `PaginatedEntities[T]` с полями `items` и `total`.

#### Scenario: Default пагинация
- **WHEN** запрос к сервисному эндпоинту не содержит параметров `limit` и `offset`
- **THEN** backend использует `limit=100`, `offset=0`

#### Scenario: Кастомный limit
- **WHEN** запрос содержит `limit=50`
- **THEN** backend возвращает не более 50 элементов

#### Scenario: Кастомный offset
- **WHEN** запрос содержит `offset=200`
- **THEN** backend пропускает первые 200 элементов и возвращает следующую страницу

### Requirement: Ограничение максимального limit
Параметр `limit` MUST быть ограничен значением 5000. Значения `limit > 5000` MUST возвращать ошибку валидации.

#### Scenario: Limit превышает максимум
- **WHEN** запрос содержит `limit=10000`
- **THEN** backend возвращает `400` с ошибкой валидации

#### Scenario: Limit равен максимуму
- **WHEN** запрос содержит `limit=5000`
- **THEN** backend возвращает до 5000 элементов

#### Scenario: Отрицательный limit
- **WHEN** запрос содержит `limit=-1`
- **THEN** backend возвращает `400` с ошибкой валидации

### Requirement: Отрицательный offset
Параметр `offset` MUST быть неотрицательным целым числом. Отрицательные значения MUST возвращать ошибку валидации.

#### Scenario: Отрицательный offset
- **WHEN** запрос содержит `offset=-10`
- **THEN** backend возвращает `400` с ошибкой валидации

### Requirement: Поле total для навигации
Поле `total` в ответе MUST содержать общее количество записей, соответствующих фильтрам (без учёта limit/offset). Если `total > offset + len(items)`, клиент MUST сделать следующий запрос с увеличенным `offset`.

#### Scenario: Есть следующая страница
- **WHEN** `total=500`, `offset=0`, `limit=100`
- **THEN** `items` содержит 100 элементов, `total=500`; клиент понимает, что нужно запросить следующую страницу

#### Scenario: Последняя страница
- **WHEN** `total=500`, `offset=400`, `limit=100`
- **THEN** `items` содержит 100 элементов, `total=500`; следующий запрос с `offset=500` вернёт пустой `items`

#### Scenario: Результат меньше лимита
- **WHEN** `total=50`, `offset=0`, `limit=100`
- **THEN** `items` содержит 50 элементов, `total=50`; все данные получены
