# seo-entity-listing

## Purpose

Получение поисковых запросов и страниц сайта конюшни списком с регистронезависимым поиском, сортировкой по значению и пагинацией.

## Requirements

### Requirement: Список поисковых запросов конюшни
`GET /api/search-queries` SHALL возвращать `200` с `{"items": [{"id", "query", "created_at"}], "total"}` только для конюшни из `X-Equestrian-Id`. `total` MUST учитывать поиск и не зависеть от пагинации.

#### Scenario: Только своя конюшня
- **WHEN** у конюшни A два запроса, у B — один, и запрашивается список A
- **THEN** `items` содержит два запроса A, `total` равен 2

### Requirement: Список страниц конюшни
`GET /api/pages` SHALL возвращать `200` с `{"items": [{"id", "page", "created_at"}], "total", "metrics_table"}` только для конюшни из `X-Equestrian-Id`, с теми же правилами поиска и пагинации, что и список запросов. `metrics_table` SHALL соответствовать capability `metrics-table-contract` и содержать колонки периода со значениями выбранного показателя для страниц из `items`. `total` MUST учитывать поиск и не зависеть от пагинации и от наличия статистики.

#### Scenario: Пустая конюшня
- **WHEN** у конюшни нет страниц
- **THEN** ответ `200` с `{"items": [], "total": 0, "metrics_table": {...}}`, где `metrics_table` содержит период и колонки с пустыми `values`; ya-metrica не вызывается

#### Scenario: Страницы со статистикой
- **WHEN** у конюшни 3 страницы, у двух есть визиты за последние 7 дней, запрос без параметров метрик
- **THEN** `items` содержит 3 страницы, `metrics_table` содержит 7 колонок дней показателя «Визиты», ячейки есть только у двух страниц

### Requirement: Регистронезависимый поиск
Параметр `search` SHALL фильтровать по вхождению подстроки в значение (`query` или `page`) без учёта регистра. `%`, `_` и `\` MUST трактоваться буквально. Поиск, пустой после trim, MUST игнорироваться.

#### Scenario: Поиск без учёта регистра
- **WHEN** есть `"Купить лошадь"` и `"Аренда денника"`, запрашивается `search=ЛОШАД`
- **THEN** возвращается только `"Купить лошадь"`

#### Scenario: Спецсимволы LIKE
- **WHEN** есть страницы `"/a_b"` и `"/axb"`, запрашивается `search=a_b`
- **THEN** возвращается только `"/a_b"`

### Requirement: Сортировка
Параметр `ordering` SHALL принимать `query`/`-query` для запросов. Для страниц он SHALL принимать `page`/`-page`, `created_at`/`-created_at` и `metric:<YYYY-MM-DD>`/`-metric:<YYYY-MM-DD>` (сортировка по колонке периода). Без параметра список MUST сортироваться по `created_at` по убыванию. Вторичный ключ `id` MUST делать порядок детерминированным. Другое значение, включая некорректную дату в `metric:`, MUST давать `400`.

#### Scenario: Сортировка по умолчанию
- **WHEN** запросы созданы последовательно `X`, затем `Y`, и `ordering` не передан
- **THEN** `Y` идёт раньше `X`

#### Scenario: Сортировка по значению
- **WHEN** запрашивается `ordering=-page`
- **THEN** страницы упорядочены по `page` по убыванию

#### Scenario: Сортировка страниц по дате создания
- **WHEN** страницы созданы последовательно `A`, затем `B`, и запрашивается `ordering=created_at`
- **THEN** `A` идёт раньше `B`

#### Scenario: Неизвестная сортировка
- **WHEN** запрашивается `ordering=created_at` или `ordering=page` для списка запросов либо `ordering=metric:2026-13-40` для страниц
- **THEN** ответ `400`

### Requirement: Пагинация
Параметры `limit` (по умолчанию 20) и `offset` (по умолчанию 0) SHALL ограничивать выдачу; `limit` MUST приводиться к диапазону 1..100, отрицательный `offset` — к 0. Нечисловые значения MUST давать `400`.

#### Scenario: Ограничение limit
- **WHEN** запрашивается `limit=500`
- **THEN** возвращается не более 100 элементов, `total` равен полному количеству

#### Scenario: Нечисловой offset
- **WHEN** запрашивается `offset=abc`
- **THEN** ответ `400`

### Requirement: Параметры метрик списка страниц
`GET /api/pages` SHALL принимать `mode`, `metric`, `date_from` и `date_to` и разрешать по ним период по capability `seo-metrics-period`. Колонки и итоговый период SHALL возвращаться в `metrics_table`. Неизвестный `mode` или `metric`, некорректная дата и нарушения правил периода MUST давать `400` до обращения к БД и ya-metrica.

#### Scenario: Обрезанный диапазон
- **WHEN** сегодня `2026-10-26`, запрошено `mode=day&date_from=2026-09-01&date_to=2026-10-26`
- **THEN** `metrics_table.period` содержит `date_to=2026-10-01`, `clamped=true`, `requested_date_to=2026-10-26`, колонок 31

#### Scenario: Невалидный режим
- **WHEN** запрошено `mode=quarter`
- **THEN** ответ `400`, ya-metrica не вызывается

### Requirement: Сортировка по колонке метрики
При `ordering=[-]metric:<дата>`, если колонка есть в разрешённом периоде, seo-service SHALL:

1. получить у ya-metrica ранжирование по границам этой колонки;
2. выполнить фильтр `search`, упорядочивание и пагинацию в SQL своей БД: сначала страницы с данными в порядке ранжирования, затем страницы без данных — в порядке по умолчанию.

Сортировка и фильтрация в памяти MUST NOT выполняться.

#### Scenario: Убывание по визитам с поиском
- **WHEN** в колонке `2026-10-20` у `/a` 9 визитов, у `/ab` — 5, у `/abc` данных нет, у `/x` — 20; запрошено `search=a&ordering=-metric:2026-10-20`
- **THEN** `items` идут в порядке `/a`, `/ab`, `/abc`, `total=3`; `/x` в выдаче нет

#### Scenario: Пагинация по ранжированию
- **WHEN** ранжировано 30 страниц, запрошено `ordering=-metric:2026-10-20&limit=10&offset=10`
- **THEN** возвращаются страницы с 11-й по 20-ю позицию ранжирования

### Requirement: Сортировка по колонке вне периода
Если колонки из `ordering=[-]metric:<дата>` в разрешённом периоде нет, ya-metrica MUST NOT вызываться для ранжирования. В этом случае применяется сортировка по умолчанию, а `metrics_table.ordering` равно `null`.

#### Scenario: Колонка вне периода
- **WHEN** запрошено `ordering=metric:2026-09-01`, а период — `2026-10-20 … 2026-10-26`
- **THEN** ответ `200` с сортировкой по умолчанию и `metrics_table.ordering=null`; ранжирование не запрашивается

### Requirement: Получение агрегатов из ya-metrica
seo-service SHALL получать агрегаты только у ya-metrica-service по адресу `YA_METRICA_SERVICE_URL` и только двумя вызовами:

- M3 `table` — с границами всех колонок периода и UUID страниц текущей выборки;
- M4 `ranking` — только при сортировке по колонке периода.

Конюшня передаётся как `equestrian_id` из `X-Equestrian-Id`, без credentials. Полученные данные MUST только преобразовываться в `metrics_table`, без повторной агрегации.

#### Scenario: ya-metrica недоступна
- **WHEN** ya-metrica отвечает `400`, не отвечает до таймаута, даёт транспортную ошибку или тело неверной схемы
- **THEN** seo-service отвечает `502` с безопасным `detail`, без тела ответа ya-metrica

### Requirement: Отсутствие N+1 в списке страниц
На один запрос списка страниц MUST выполняться не более двух вызовов ya-metrica и ровно два SQL-запроса к БД seo-service (выборка и `total`), независимо от `limit`. При пустой выборке без сортировки по метрике ya-metrica не вызывается.

#### Scenario: Без сортировки по метрике
- **WHEN** запрошен список с `limit=50` и `ordering=-page`
- **THEN** выполняются один вызов `table` с UUID 50 страниц выборки и границами колонок периода и два SQL-запроса к БД seo-service

#### Scenario: С сортировкой по метрике
- **WHEN** запрошен список с `ordering=metric:2026-10-20`, колонка есть в периоде
- **THEN** выполняются вызов `ranking` с границами `2026-10-20..2026-10-20`, затем вызов `table`, а также два SQL-запроса к БД seo-service
