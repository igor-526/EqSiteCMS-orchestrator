# vk-confirmation Specification

## Purpose
Подтверждение владения аккаунтом VK по человекочитаемой контрольной строке: генерация с TTL, инвалидация предыдущих кодов, сверка кода из сообщения бота, ограничение попыток, журналирование и отвязка.

## Requirements

### Requirement: Таблица vk_confirmations

`vk-service` MUST создать таблицу `vk_confirmations` с полями: `id` (UUID, PK), `user_vk_id` (UUID, FK на `user_vks.id`, NOT NULL), `code` (String(16), NOT NULL), `expires_at` (TIMESTAMPTZ, NOT NULL), `created_at` (TIMESTAMPTZ, NOT NULL), `used_at` (TIMESTAMPTZ, nullable). MUST существовать unique index `ix_vk_confirmations_code` на `code`.

#### Scenario: Создание таблицы

- **WHEN** применяется миграция VK-домена
- **THEN** таблица `vk_confirmations` MUST существовать со всеми перечисленными полями

#### Scenario: Unique constraint на code

- **WHEN** выполняется вставка записи с существующим `code`
- **THEN** MUST возникнуть ошибка unique constraint violation

### Requirement: Генерация человекочитаемой контрольной строки

`vk-service` MUST генерировать `code` длиной `VK_CONFIRMATION_CODE_LENGTH` (по умолчанию `8`) из алфавита `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` с использованием `secrets.choice`. Алфавит MUST NOT содержать символы `I`, `O`, `0`, `1`. Код MUST храниться в верхнем регистре. При коллизии unique index генерация MUST повторяться, но не более 5 раз, после чего MUST подниматься доменная ошибка.

#### Scenario: Длина и алфавит кода

- **WHEN** генерируется новый код с настройками по умолчанию
- **THEN** длина MUST быть `8`, а каждый символ MUST принадлежать разрешённому алфавиту

#### Scenario: Отсутствие неоднозначных символов

- **WHEN** сгенерировано 1000 кодов
- **THEN** ни один код MUST NOT содержать `I`, `O`, `0` или `1`

#### Scenario: Уникальность кодов

- **WHEN** генерируются два кода подряд
- **THEN** они MUST быть различны

#### Scenario: Криптографический источник случайности

- **WHEN** reviewer читает реализацию генератора
- **THEN** MUST использоваться модуль `secrets`, а `random` MUST NOT использоваться

### Requirement: TTL контрольной строки

`vk-service` MUST вычислять `expires_at = now() + VK_CONFIRMATION_TTL_MINUTES`. Значение по умолчанию — `30` минут.

#### Scenario: Вычисление TTL

- **WHEN** создаётся запись подтверждения
- **THEN** `expires_at` MUST быть равен `created_at + VK_CONFIRMATION_TTL_MINUTES`

#### Scenario: Значение TTL по умолчанию

- **WHEN** переменная `VK_CONFIRMATION_TTL_MINUTES` не задана
- **THEN** TTL MUST быть `30` минут

### Requirement: Выдача контрольной строки владельцу

`vk-service` MUST предоставлять доменную операцию выдачи контрольной строки по `user_id`. Операция MUST быть идемпотентной по владельцу: если non-deleted запись `user_vks` отсутствует, она MUST создаваться в состоянии `PENDING`; если запись существует, она MUST переиспользоваться. Все предыдущие non-used коды этой записи MUST помечаться `used_at = now()` до создания нового кода. Операция MUST возвращать код, `expires_at` и текущее состояние привязки.

#### Scenario: Первая выдача кода

- **WHEN** у пользователя нет non-deleted записи `user_vks` и запрошена выдача кода
- **THEN** MUST быть создана запись со `state="PENDING"` и возвращён новый код с `expires_at`

#### Scenario: Повторная выдача инвалидирует предыдущий код

- **WHEN** у пользователя есть non-used код и запрошена повторная выдача
- **THEN** предыдущий код MUST получить `used_at = now()`, а новый код MUST быть создан и возвращён

#### Scenario: Выдача кода при активной привязке

- **WHEN** у пользователя запись в состоянии `ACTIVE` и запрошена выдача кода
- **THEN** запрос MUST быть отклонён доменной ошибкой конфликта, поскольку VK уже привязан

#### Scenario: Выдача кода при заблокированном боте

- **WHEN** у пользователя запись в состоянии `BLOCKED` и запрошена выдача кода
- **THEN** запрос MUST быть отклонён доменной ошибкой конфликта с указанием, что нужно разрешить сообщения от группы, а не привязывать заново

#### Scenario: Истёкший PENDING не блокирует выдачу

- **WHEN** у пользователя запись `PENDING` с истёкшим кодом и запрошена выдача
- **THEN** запись MUST переиспользоваться, а новый код MUST быть выдан

### Requirement: Подтверждение привязки по контрольной строке

`vk-service` MUST предоставлять доменную операцию подтверждения, принимающую нормализованный `code` и данные VK-отправителя (`vk_peer_id`, опциональные `vk_screen_name`, `vk_display_name`). Нормализация MUST удалять окружающие пробелы и приводить код к верхнему регистру. Операция MUST проверять существование кода, `used_at IS NULL`, `expires_at > now()`, отсутствие конфликта `vk_peer_id`, после чего MUST устанавливать `vk_peer_id`, `state="ACTIVE"`, кэш имён в `user_vks` и `used_at = now()` в `vk_confirmations`.

#### Scenario: Успешное подтверждение

- **WHEN** передан валидный код с `used_at IS NULL` и `expires_at > now()`, а `vk_peer_id` свободен
- **THEN** привязка MUST перейти в `ACTIVE` с указанным `vk_peer_id`, код MUST быть помечен использованным, а операция MUST вернуть успешный результат с `user_id`

#### Scenario: Регистронезависимое сопоставление

- **WHEN** передан код в нижнем регистре с окружающими пробелами
- **THEN** он MUST быть нормализован и успешно сопоставлен с сохранённым кодом

#### Scenario: Несуществующий код

- **WHEN** переданный код отсутствует в БД
- **THEN** операция MUST вернуть доменную ошибку «код недействителен» и MUST NOT изменять данные

#### Scenario: Уже использованный код

- **WHEN** у найденного кода `used_at IS NOT NULL`
- **THEN** операция MUST вернуть доменную ошибку «код уже использован» и MUST NOT изменять данные

#### Scenario: Истёкший код

- **WHEN** у найденного кода `expires_at <= now()`
- **THEN** операция MUST вернуть доменную ошибку «срок действия кода истёк» и MUST NOT изменять данные

#### Scenario: VK-аккаунт уже привязан к другому пользователю

- **WHEN** переданный `vk_peer_id` уже принадлежит другой non-deleted записи
- **THEN** операция MUST вернуть доменную ошибку конфликта, MUST NOT переносить привязку и MUST NOT помечать код использованным

#### Scenario: Повторная доставка того же подтверждения идемпотентна

- **WHEN** то же сообщение с тем же кодом обрабатывается повторно, а привязка уже `ACTIVE` с тем же `vk_peer_id`
- **THEN** операция MUST вернуть результат «уже подтверждено» без второй записи и без ошибки уровня инфраструктуры

### Requirement: Ограничение попыток подтверждения

`vk-service` MUST ограничивать число неуспешных попыток подтверждения на один `vk_peer_id`: не более `VK_CONFIRMATION_MAX_ATTEMPTS` (по умолчанию `5`) за окно `VK_CONFIRMATION_ATTEMPT_WINDOW_MINUTES` (по умолчанию `10`). Подсчёт MUST выполняться по записям `vk_logs` с `action="vk_confirmation"` и неуспешным `status`. При превышении лимита операция MUST отклонять запрос без обращения к `vk_confirmations`.

#### Scenario: Лимит не превышен

- **WHEN** у `vk_peer_id` менее `VK_CONFIRMATION_MAX_ATTEMPTS` неуспешных попыток в окне
- **THEN** очередная попытка MUST обрабатываться обычным порядком

#### Scenario: Лимит превышен

- **WHEN** у `vk_peer_id` достигнут `VK_CONFIRMATION_MAX_ATTEMPTS` неуспешных попыток в окне
- **THEN** операция MUST вернуть доменную ошибку rate limit, MUST NOT искать код и MUST записать в журнал `status="rate_limited"`

#### Scenario: Окно истекло

- **WHEN** все неуспешные попытки старше `VK_CONFIRMATION_ATTEMPT_WINDOW_MINUTES`
- **THEN** попытка MUST обрабатываться обычным порядком

### Requirement: Журналирование попыток подтверждения

`vk-service` MUST записывать в `vk_logs` каждую попытку подтверждения независимо от результата с `action="vk_confirmation"` и `status` из множества `success`, `already_confirmed`, `not_found`, `used`, `expired`, `peer_conflict`, `rate_limited`, `error`. Полная контрольная строка MUST NOT попадать в журнал и логи: MUST сохраняться только маскированное значение (первые два символа и длина).

#### Scenario: Журналирование успеха

- **WHEN** подтверждение выполнено успешно
- **THEN** MUST быть создана запись `vk_logs` со `status="success"` и `details`, содержащими `user_id`, `user_vk_id`, `vk_peer_id` и маскированный код

#### Scenario: Журналирование каждого отказа

- **WHEN** подтверждение отклонено по любой причине
- **THEN** MUST быть создана запись `vk_logs` с соответствующим `status` и `vk_peer_id` в `details`

#### Scenario: Секрет не раскрывается

- **WHEN** reviewer читает записи `vk_logs` и вывод логов сервиса
- **THEN** полная контрольная строка MUST NOT присутствовать ни в одном поле

### Requirement: Отвязка VK владельцем

`vk-service` MUST предоставлять доменную операцию отвязки по `user_id`, которая MUST выполнять soft-delete записи `user_vks`, помечать все non-used коды использованными и журналировать действие с `action="vk_unlink"`. Операция MUST быть идемпотентной.

#### Scenario: Успешная отвязка

- **WHEN** у пользователя есть non-deleted запись и запрошена отвязка
- **THEN** запись MUST получить `deleted_at`, коды MUST быть инвалидированы, а в `vk_logs` MUST появиться запись `action="vk_unlink"`, `status="success"`

#### Scenario: Идемпотентная отвязка

- **WHEN** у пользователя нет non-deleted записи и запрошена отвязка
- **THEN** операция MUST завершиться успешно и записать в журнал `status="noop"`

#### Scenario: Повторная привязка после отвязки

- **WHEN** после отвязки пользователь запрашивает новый код и подтверждает его тем же `vk_peer_id`
- **THEN** MUST быть создана новая non-deleted запись в состоянии `ACTIVE`
