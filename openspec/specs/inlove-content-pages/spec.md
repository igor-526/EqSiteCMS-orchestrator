# Purpose

Зафиксировать серверные контентные страницы INLOVE, общие контакты, SEO, безопасность и адаптивность.

## Requirements

### Requirement: Серверная главная страница
Маршрут `/` SHALL выводить в порядке scheme.md hero с CTA и доступной локальной фотографией из материалов клуба, четыре квадратные карточки занятий/прогулок/абонементов/постоя с подходящими статическими иконками, преимущества программ, преимущества клуба, последнюю опубликованную новость со slug-ссылкой и ссылкой на архив, контакты. Вариативные тексты MUST поступать из `site_settings`, бизнес-сущности — из профильных Public Read API. Блок стоимости MUST отсутствовать; hero MUST не зависеть от price API. Все индексируемые блоки MUST содержаться в завершённом серверном HTML без browser fetch.

#### Scenario: Полная главная без JavaScript
- **WHEN** crawler запрашивает `/` при доступных settings/news
- **THEN** серверный HTML содержит все перечисленные блоки, одну новость, четыре service cards и фотографию hero, без блока стоимости, ровно один h1 и SEO metadata

#### Scenario: Независимая деградация
- **WHEN** news возвращает ошибку либо пустой список
- **THEN** hero и контакты остаются, для услуг доступны ссылки, пустая новость скрывается при сохранении ссылки на архив, ошибка не подменяется сообщением об отсутствии данных

### Requirement: Серверная страница О клубе
`/about` SHALL выводить вступление, окружение/инфраструктуру, галерею, одобренную команду, сводку отзывов без копирования отзывов, переиспользуемые с главной контакты и CTA. Блоки оплаты и обработки персональных данных MUST отсутствовать. Settings MUST использовать ключи `about.*`, `team.people`, `reviews.summary`; пустые необязательные блоки скрываются независимо. Галерея MUST использовать `/api/photos?limit=24&sort=created_at`, редакционный список photo IDs пересекать с доступной выборкой, без выдуманного `include_ids`.

#### Scenario: Неполные настройки
- **WHEN** team/reviews отсутствуют, JSON одного блока невалиден и photos недоступны
- **THEN** страница сохраняет вступление из site-settings и контакты, не создаёт фиктивные отзывы/сотрудников и не падает целиком

#### Scenario: Редакционный текст и общие контакты
- **WHEN** пользователь открывает `/about` без JavaScript после обновления settings
- **THEN** HTML содержит новый текст из `about.*`, общую с главной композицию контактов, только явно одобренную команду и не содержит блоки оплаты/privacy или ссылки на удалённый `/about#privacy`

### Requirement: Общий блок контактов
Главная и `/about` MUST переиспользовать один ContactSection с тремя строками существующих контактных каналов, подходящими статическими иконками, названием «VK» и кнопкой «Обратный звонок». Все ссылки этого блока MUST иметь `target="_blank"` и `rel="noopener noreferrer"`. Карта MUST формировать iframe widget URL аналогично `services/site-ad/src/ui/media/MapEmbed.tsx` из координат site-settings, а не использовать URL карточки организации в качестве iframe src; ссылка на маршрут остаётся отдельной. Отсутствующие контактные данные MUST не выдумываться.

#### Scenario: Контакты и карта на обеих страницах
- **WHEN** настройки содержат три контактных канала и координаты клуба
- **THEN** обе страницы содержат одинаковые три строки с иконками и VK, рабочий iframe widget с этими координатами и ссылки в новых вкладках; callback сохраняет контекст текущей страницы

### Requirement: Общие SSR SEO и адаптивность
Все страницы этого change MUST использовать существующий дизайн и компоненты 069, один h1, доступные изображения и ссылки, серверные title/description/canonical. Контент SHALL быть доступен при выключенном JavaScript на desktop/tablet/mobile; клиентские острова разрешены для callback, галереи и других взаимодействий. Ошибка selector MUST не маскироваться данными другого tenant. HTML из CMS MUST проходить серверный allowlist sanitizer; обычные settings рендерятся как текст.

#### Scenario: Адаптивная доступность
- **WHEN** страницы открываются на ширинах 375, 768 и 1440 px, с длинным текстом и keyboard-only navigation
- **THEN** нет горизонтального overflow, порядок секций логичен, CTA доступны, focus виден, reduced motion соблюдён

#### Scenario: Серверная безопасность и SEO
- **WHEN** CMS поле содержит script, обработчик события или javascript URL
- **THEN** исполняемое содержимое не попадает в HTML, полезный безопасный текст сохраняется и metadata доступна до hydration
